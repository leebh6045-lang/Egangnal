# Egangnal 项目技术与代码导览

本文面向第一次阅读 Egangnal 代码的人，目标不是逐行解释所有实现，而是先建立一张可靠的项目地图：应用由什么技术构成、代码如何分层、一次用户操作会经过哪些文件，以及遇到某类需求时应该从哪里开始查找。

> 文档基线：Egangnal `1.0.2 (3)`，Swift 6，macOS 15.0+。本文以当前工作区代码为准，而不是以历史草图或尚未同步的旧说明为准。

## 1. 先用一句话理解项目

Egangnal 是一个本地优先的 macOS 语言学习应用。界面由 SwiftUI 构建，页面状态由 Observation 驱动，单词和学习时长通过 SwiftData 持久化，少量 macOS 专属能力通过 AppKit 完成，应用更新由 Sparkle 提供。

项目并不是严格套用某一种架构模板。更准确的描述是：

```text
SwiftUI 页面（View / Feature）
        ↓ 用户意图与状态展示
可观察状态（Store / Controller）
        ↓ 业务接口
领域规则与仓储协议（Domain / Protocol）
        ↓ 具体实现
SwiftData、UserDefaults、文件系统、AVFoundation、Sparkle
```

这样分层的主要目的，是让界面不用知道数据库如何查询，让业务规则可以脱离窗口单独测试，也让系统服务可以在 UI 测试中替换成内存或静音实现。

## 2. 技术栈

| 技术 | 在项目中的作用 | 是否属于第三方 |
| --- | --- | --- |
| Swift 6 | 编写应用、业务规则和测试的主要语言 | 否 |
| SwiftUI | 应用生命周期、页面、布局、按钮、动画和环境值 | 否 |
| Observation | 使用 `@Observable` 让 Store 的变化自动刷新界面 | 否 |
| SwiftData | 保存单词、导入批次、单词出现日期、累计时长和每日活动 | 否 |
| Foundation | 日期、字符串、文件、UserDefaults 和基础类型 | 否 |
| AppKit | macOS 窗口外观、应用生命周期、主题波纹截图等能力 | 否 |
| UniformTypeIdentifiers | 描述 Markdown 文档类型，配合导入和导出面板 | 否 |
| AVFoundation | 播放单词刷选择题提交反馈音效，并支持在设置页试听 | 否 |
| OSLog | 记录音频播放等系统日志 | 否 |
| Sparkle 2.9.6 | 在设置页提供应用内检查更新 | 是 |
| Swift Testing | 单元测试中的 `@Test`、`#expect` 等 API | 否 |
| XCTest / XCUITest | 驱动真实 macOS 窗口进行 UI 自动化测试 | 否 |

工程由 Xcode 16.4 创建，主 target 是 `Egangnal`，另外还有 `EgangnalTests` 和 `EgangnalUITests` 两个测试 target。构建环境需要支持 Swift 6 和 macOS 15 SDK，部署目标为 macOS 15.0。

### 2.1 SwiftData 和 SQLite 的关系

业务代码只使用 SwiftData 的模型、`ModelContainer` 和 `ModelContext`，没有直接编写 SQL。具体磁盘格式和存储位置由系统管理，页面和仓储都不应把 SQLite 文件结构当作稳定接口。

这意味着：

- View 不直接执行数据库查询。
- Repository 负责把 SwiftData 对象转换为页面需要的快照。
- 以后即使调整存储实现，页面层也不必跟着大改。
- 不需要像 MySQL 一样单独安装数据库服务或启动端口。

## 3. 从哪里开始读

第一次阅读时，推荐按下面顺序打开文件：

1. [`Egangnal/EgangnalApp.swift`](../Egangnal/EgangnalApp.swift)：找到应用入口和窗口。
2. [`Egangnal/App/AppDependencies.swift`](../Egangnal/App/AppDependencies.swift)：理解全局对象如何被创建。
3. [`Egangnal/ContentView.swift`](../Egangnal/ContentView.swift)：理解首页、设置页和语言工作区如何切换。
4. [`Egangnal/Domain/LanguageSpace.swift`](../Egangnal/Domain/LanguageSpace.swift) 与 [`Egangnal/Domain/WorkspaceFeature.swift`](../Egangnal/Domain/WorkspaceFeature.swift)：理解语言和功能两个核心枚举。
5. [`Egangnal/Features/Dashboard/DashboardView.swift`](../Egangnal/Features/Dashboard/DashboardView.swift)：阅读首页组合方式。
6. [`Egangnal/Features/LanguageSpace/WorkspaceShell.swift`](../Egangnal/Features/LanguageSpace/WorkspaceShell.swift)：阅读工作区顶部栏和功能容器。
7. 选择一个垂直功能继续向下读，例如单词刷的 `WordQuizView → WordQuizStore → WordQuizEngine`。

不要一开始就阅读 `ThemeRippleTransition`、`StudyTimeController` 或完整的 SwiftData 仓储。它们包含动画快照、生命周期、持久化失败恢复等复杂边界，适合建立基础地图后再看。

## 5. 分层职责

### 5.1 App：应用级入口和组装

`App` 层回答的问题是：“应用如何启动、全局依赖从哪里来、页面路由和 macOS 窗口如何工作？”

| 文件 | 职责 |
| --- | --- |
| `EgangnalApp.swift` | `@main` 入口；创建主窗口；注入 SwiftData 容器；设置最小尺寸、隐藏标题栏和菜单命令 |
| `ContentView.swift` | 根路由；组合首页、设置和语言功能页；把全局环境值向下传递；根据路由和应用生命周期同步计时 |
| `AppDependencies.swift` | Composition Root；一次性创建 ModelContainer、Repository、Store、音效播放器和更新控制器 |
| `AppRoute.swift` | 描述 `.dashboard`、`.settings`、`.workspace` 三类根页面状态 |
| `AppCommands.swift` | 定义菜单命令和 `Command + 1 / 2 / 3` 功能导航 |
| `AppDelegate.swift` | 处理 macOS 应用级委托行为，例如关闭最后窗口后退出 |
| `WindowAppearanceConfigurator.swift` | 用 AppKit 配置标题栏、背景、窗口外观和 UI 测试窗口尺寸 |
| `AppUpdateController.swift` | 用项目自己的协议包住 Sparkle，为设置页暴露“检查更新”能力 |

`AppDependencies` 是理解项目所有权最重要的文件。一个全局对象应当在哪里创建、正式环境和 UI 测试如何替换实现，都应优先在这里寻找答案。

### 5.2 Domain：数据含义和业务规则

`Domain` 层回答的问题是：“这个概念是什么，它有哪些合法状态，规则如何计算？”这一层尽量不依赖具体页面。

| 文件 | 职责 |
| --- | --- |
| `LanguageSpace.swift` | 定义英语、日语空间及显示名称、封面资源、配对语言 |
| `WorkspaceFeature.swift` | 定义单词本、单词刷、学习资料；声明顺序也是顶部栏顺序 |
| `AppPersonalization.swift` | 定义语言封面和网格背景两个个性化开关，并注册 SwiftUI Environment 值 |
| `CalendarMonth.swift` | 计算某月天数、固定 6 行日历网格和同年月份移动 |
| `DailyStudyFeedback.swift` | 定义本地日期键、当日访问/达标状态以及 15 分钟阈值 |
| `StudyTimeModels.swift` | 定义累计学习时长和每日学习活动的 SwiftData 模型 |
| `UserProfile.swift` | 定义本地用户昵称模型；当前仍存在，但首页未接入个人信息面板 |
| `WordBookModels.swift` | 定义文档日期、解析结果、页面快照和三种 SwiftData 单词模型 |
| `WordBookMarkdown.swift` | 生成空白模板；解析并校验 Markdown；按语言规范化词形 |
| `WordBookPresentation.swift` | 定义分页/日期浏览模式、遮盖状态和每页 20 条规则 |
| `WordBookTemplateDocument.swift` | 把模板文本适配成 SwiftUI `FileDocument` |
| `WordQuizModels.swift` | 定义测试范围、难度、题型、题目、答案、轮次和结果值 |
| `WordQuizEngine.swift` | 完成随机抽题、干扰项生成、判题、深度模式组卷和错题重试 |
| `WordQuizSoundEffect.swift` | 定义两种答题音效和关闭选项 |

其中 `WordQuizEngine` 是很典型的纯业务对象：它不画按钮、不操作数据库，也不播放声音，只接收候选词并返回测试会话，因此非常适合单元测试。

### 5.3 Data：持久化和系统边界

`Data` 层回答的问题是：“数据从哪里读取、如何保存、发生失败时怎样处理？”

| 文件 | 职责 |
| --- | --- |
| `ProfileRepository.swift` | 读取和保存主用户昵称；当前依赖仍被创建，但对应面板没有挂到首页 |
| `StudyTimeRepository.swift` | 读取和保存每种语言的累计秒数，标记每日进入状态，并合并按日期拆分的学习增量 |
| `WordBookRepository.swift` | 单词导入、去重、首次释义优先、查询、增删改和事务失败回滚 |
| `WordQuizCandidateSource.swift` | 把单词仓储快照转换为单词刷候选池，并排除没有文档日期的手动词条 |
| `ExportDirectoryService.swift` | 保存安全作用域书签、向默认目录导出模板、处理失效目录和文件重名 |

仓储通常先声明协议，再提供 SwiftData 实现。页面依赖协议而不是具体类型，因此 Preview、单元测试和 UI 测试能够使用假实现或内存数据库。

### 5.4 Stores：可观察状态和流程协调

`Stores` 层回答的问题是：“用户刚刚做了什么，页面现在应该显示什么，下一步调用哪个业务对象？”

| 文件 | 职责 |
| --- | --- |
| `AppearanceStore.swift` | 读取、切换和保存应用自己的浅色/深色主题 |
| `AppSettingsStore.swift` | 管理封面、网格、答题音效和默认导出目录偏好 |
| `WorkspaceNavigationStore.swift` | 分别记住英语、日语上次打开的工作区功能 |
| `StudyTimeController.swift` | 全局唯一计时状态机；协调路由、前后台、睡眠、跨午夜和检查点保存 |
| `WordQuizStore.swift` | 加载候选词、锁定设置、开始会话、提交答案、推进题目和重试错题 |
| `ProfileStore.swift` | 昵称校验和保存；当前没有接入用户可见页面 |

Store 一般标记为 `@MainActor @Observable`。`@MainActor` 约束 UI 状态在主线程访问，`@Observable` 则让读取这些属性的 SwiftUI View 在值变化时重新计算 `body`。

## 6. 根调用链

### 6.1 应用启动

```text
系统启动 Egangnal
    ↓
EgangnalApp
    ↓ AppDependencies.live()
创建 ModelContainer、Repository、Store、播放器、更新器
    ↓
ContentView
    ↓ 初始 route = .dashboard
DashboardView
```

`EgangnalApp` 只负责创建窗口和注入顶层依赖，不负责具体业务。`ContentView` 根据 `AppRoute` 决定当前显示哪个页面。

### 6.2 从首页进入语言功能

```text
LanguageLauncher 的 Button
    ↓ openLanguage(space)
ContentView 查询 WorkspaceNavigationStore
    ↓ 取出该语言上次使用的功能
route = .workspace(space, feature)
    ↓
WorkspaceShell
    ↓
WordBookView / WordQuizView / WorkspaceDocumentsPlaceholder
```

路由切换还会通知 `StudyTimeController`。进入英语空间时开始或恢复英语计时；切换到日语空间前先提交英语增量，再开始日语；回首页或设置页时暂停。

### 6.3 单词导入

```text
WordBookView 打开 fileImporter
    ↓ 读取 UTF-8 Data
WordBookMarkdownParser
    ↓ 完整校验日期、分隔符、单词和词义
ParsedWordDocument
    ↓
WordBookRepository.importDocument
    ↓ 一次事务中去重和写入
WordEntry + WordImportBatch + WordOccurrence
    ↓
刷新 [WordBookEntrySnapshot]
    ↓
SwiftUI 重新显示页面
```

解析和保存是两个阶段。只有整份文件解析成功后才接触数据库；数据库保存失败时仓储回滚内存中的变化，避免出现“导入了一半”。

### 6.4 单词刷

```text
WordBookRepository
    ↓
WordQuizCandidateSource
    ↓ 候选词和可用日期
WordQuizStore
    ↓
WordQuizEngine 组卷
    ↓
WordQuizSession / WordQuizRound
    ↓
WordQuizView 提交答案
    ↓
判题、反馈、自动进入下一题、结算或错题再战
```

简单模式为每个抽中的单词生成一道词义选择题。深度模式先生成全部词义选择题，再生成同一批单词的拼写题。每次最多抽取 20 个单词。

### 6.5 学习计时与日历反馈

```text
ContentView 路由或应用生命周期变化
    ↓
StudyTimeController
    ↓ 使用单调时钟计算有效增量
StudyTimeRepository
    ↓
StudyTimeRecord（语言累计秒数）
DailyStudyActivity（某日本地投入）
    ↓
WorkspaceShell 显示当前语言小时数
CalendarPanel 显示灰色或金黄色日期反馈
```

两个语言各自保存长期累计值；日历颜色使用当天英语与日语的合计投入。当天进入过学习空间但合计不足 15 分钟时为灰色，达到 15 分钟时为金黄色。首页只在日历下方显示一次当天合计分钟数和目标状态，不显示跨语言长期累计。

## 7. 数据存在哪里

### 7.1 SwiftData

`AppDependencies` 注册了以下持久化模型：

| 模型 | 保存内容 |
| --- | --- |
| `UserProfile` | 昵称；当前无可见入口 |
| `StudyTimeRecord` | 每门语言的长期累计秒数 |
| `DailyStudyActivity` | 保存某个“本地日期 + 语言空间”是否进入及学习秒数；日历展示时再合并英语和日语 |
| `WordEntry` | 一个语言空间中的唯一主词条及首次释义 |
| `WordImportBatch` | 一次带文档日期的导入批次 |
| `WordOccurrence` | 主词条在哪个模板文档日期出现过 |

正式应用使用磁盘容器，不启用 CloudKit。UI 测试则使用内存容器，不污染真实用户数据。

### 7.2 UserDefaults

适合体积小、结构简单的偏好：

- 浅色或深色主题；
- 是否显示语言卡片封面；
- 是否显示细网格背景；
- 单词刷音效选择；
- 默认导出目录的安全作用域书签；
- 英语和日语上次打开的功能。

这些值不是需要复杂查询的业务数据，因此没有必要放入 SwiftData。

### 7.3 文件系统

用户可以从文件选择器读取 Markdown，并把空白模板保存到默认目录或临时选择的目录。当前单词导入会把文档解析成结构化词条，而不是把原 Markdown 复制成资料文件。

项目仍有“学习资料”入口，但当前页面只是“功能监修中”占位。旧需求文档中描述的 Markdown/纯文本资料复制与只读浏览尚未完成，不能把它当作当前已经存在的文件存储能力。

### 7.4 Sparkle 更新资源

`updates/appcast.xml` 是客户端读取的更新清单；`SparkleReleases` 保存发布过程中的包、签名和说明。Sparkle 是当前唯一第三方运行时依赖，正式 Release 会从配置的 GitHub Pages 地址检查更新。当前公开的 1.0.2 更新条目要求 macOS 15.0 和 arm64；这是发布包及更新清单的硬件边界，不等同于工程中显式设置了 `ARCHS` 限制。

## 8. 重要业务约束

理解下面这些约束，可以避免“代码能跑，但语义被破坏”的改动：

1. 同一时刻全局最多只有一种语言计时。
2. 累计时长不能由用户手工修改，也不保存每次学习会话历史。
3. 应用失活、系统睡眠和退出期间不能补算学习时间。
4. 日历达标使用当天英日合计，语言空间时长仍分别保存。
5. 同一个词的首次释义优先，后续导入不能覆盖它。
6. 高频词表示至少出现在两个不同文档日期，不是简单的重复次数。
7. 相同语言、相同日期的重复导入应保持幂等。
8. 默认 20 条分页模式只读；编辑入口只在按日期模式出现。
9. 手动新增词没有模板文档日期，因此不会进入单词刷候选池。
10. 离开正在进行的单词刷时，答题进度不持久化，必须先提示用户。

## 10. 测试结构

### 单元测试

`EgangnalTests` 使用 Swift Testing，主要文件为：

- `EgangnalTests.swift`：主题、日历、Markdown、仓储、计时、布局模型等综合测试；
- `WordQuizCandidateSourceTests.swift`：候选词和日期过滤；
- `WordQuizEngineTests.swift`：抽题、题型、判题和错题重试；
- `WordQuizStoreTests.swift`：单词刷页面状态流转。

### UI 测试

`EgangnalUITests` 使用 XCTest/XCUITest，通过启动参数切换到内存数据库、静音播放器或指定页面，并验证导航、窗口布局、辅助功能标识和关键交互。

正式依赖和测试依赖的切换集中在 `AppDependencies.live()`。新增全局服务时，也应在同一个位置提供可测试替代实现。

## 13. 维护原则

- 页面只表达布局和用户意图，不直接操作 SwiftData。
- 可以独立计算的业务规则放入 Domain，并优先写单元测试。
- 外部系统能力通过协议包裹，保持 Preview 和测试可替换。
- 应用级对象只创建一次，并由 `AppDependencies` 统一持有。
- 复杂状态尽量用枚举或明确模型表达，避免多个布尔值互相组合。
- 行为发生变化时，同步修改测试以及 `docs` 中相应设计文档。
- 新代码使用清晰英文标识符，并只在原因、约束和异常边界处写简洁中文注释。

读完本文后，可以继续阅读 [Swift 与 SwiftUI 入门教程](Swift与SwiftUI入门教程.md)，再选择一个功能沿着“View → Store → Domain/Repository”的路径实际跟读代码。
