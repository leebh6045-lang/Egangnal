# 词库界面设计

- 状态：已实现（2026-09-11）；单元测试 137/137、词库界面测试 3/3 通过
- 日期：2026-09-11
- 关联文档：[词库实现设计](词库实现设计.md)；[ADR-003](../architecture/架构决策-003-公共词库与个人单词本分离.md)；[单词本沉浸式阅读](单词本沉浸式阅读.md)
- 阶段：路线图 5.3（界面），5.4（收录）另见本文第 13 节

## 1. 目标与范围

### 1.1 目标

在英语语言空间的“学习资料”中提供可用的词库页面：按考试等级筛选、搜索、分页浏览，支持词义遮盖，并通过悬停查看音标与完整释义。

### 1.2 本阶段包含

- 替换 `WorkspaceDocumentsPlaceholder`，英语空间显示词库，日语空间继续显示占位。
- 等级筛选（全部 / 初中 / 高中 / 四级 / 六级）。
- 完整单词与首字母搜索，**以及中文释义检索**，输入即查。
- 每页 50 条、页内滚动的分页浏览。
- 单词与词性词义的逐条点击遮盖（行为与单词本一致）。
- 悬停浮层：音标、完整词性词义、等级。

### 1.3 本阶段不包含

- 收录按钮与“已收录”标记（属 5.4）。
- 单词刷联动、等级速测（属 5.5）。
- 日语词库。
- 发音音频、多义项结构化拆解、例句。

## 2. 与单词本的关系

词库**刻意沿用单词本的阅读语言**，让用户在两个功能之间不需要重新学习；差异集中在“多了什么”和“能做什么”。

### 2.1 一致的部分

| 项目 | 说明 |
| --- | --- |
| 版式 | 双栏，每行两个词条，词条内字段等宽并居中 |
| 结构 | 词条区无面板、无边框、无逐条分隔线 |
| 遮盖 | 点击单个字段切换遮盖，遮盖块外观与单词本完全相同 |
| 强调色 | 使用当前语言空间的强调色 |
| 字体族 | 系统字体，字号通过 `AppTheme` 常量统一 |

### 2.2 刻意不同的部分

| 项目 | 单词本 | 词库 | 目的 |
| --- | --- | --- | --- |
| 主字号 | 30pt | **24pt** | 一屏可见约 10 个词；长单词更少换行 |
| 释义内容 | 纯中文意思 | **带词性前缀**（`vt. 放弃…`） | 一眼可辨；信息更有用 |
| 释义行数 | 可换行 | **固定单行，尾部截断** | 保证网格等高整齐 |
| 顶部 | 标题 + 下拉工具栏 | **等级筛选 + 搜索框 + 结果条数** | 词库的主操作是“查” |
| 悬停 | 无 | **音标 + 完整释义 + 等级** | 承载全部附加信息 |
| 翻页 | 20 条/页，固定不滚动 | **50 条/页，页内滚动** | 7,116 条不适合小页翻页 |

## 3. 页面结构

```text
  ‹   英语词库                                              7,116 条
  ────────────────────────────────────────────────────────────────
       全部   初中   高中   四级   六级     ⌕ 输入单词、首字母或中文意思
       ────
  ────────────────────────────────────────────────────────────────
  ┌ 滚动区 ────────────────────────────────────────────────────┐
  │      abandon                                 abbreviation  │
  │   vt. 放弃, 抛弃, 遗弃…                   n. 缩写, 缩短, 缩写词 │
  │                                                            │
  │      abide                                     ability     │
  │   vi. 遵守, 持续, 忍受                      n. 能力, 本领, 才能 │
  └────────────────────────────────────────────────────────────┘
                  ‹   第 1 / 143 页 · 1–50 条   ›
```

- 顶部标题行、检索区、底部分页区**固定**，只有词条区滚动。
- 左侧内容统一使用 `AppTheme.contentPadding` 作为基线，返回箭头的可见图形与标题左边缘对齐（沿用《页面对齐与图标精简》的规则）。
- 检索区上下各有一条 `palette.border.opacity(0.5)` 的分隔线，把“工具区”和“内容区”分开。

## 4. 词块规格

每个词块**两行**：单词在上、词性词义在下，两行都居中；一行放两个词块，用 `LazyVGrid` 两列等宽排布。

> **与单词本的差异**：单词本是"单词、释义、单词、释义"四栏横排；词库改为上下两行。原因是词库的释义带上了 `vt.` 这类词性前缀后更长，需要整列宽度才放得下，四栏横排会把释义挤成频繁换行。

| 项目 | 数值 | 说明 |
| --- | --- | --- |
| 单词字号 | 24pt，semibold | `palette.primaryText` |
| 词性词义字号 | 20pt，regular | `palette.primaryText` |
| 字段间距 | 8pt | 单词与其释义之间 |
| 词块最小高度 | 64pt | 保证空音标时行高不塌 |
| 网格行间距 | 28pt | 行与行之间 |
| 网格列间距 | 32pt | 复用 `wordBookEntryColumnSpacing` |
| 释义行数 | 1 行，`truncationMode(.tail)` | 超长显示 `…` |

默认显示的词性词义由新增的**浏览级短释义**规则产生：保留词性前缀，取首个词性组，最长 16 个字符，超出加 `…`。它与单词刷使用的 `gloss-v1`（剥离词性、12 字符）是两个不同用途的规则，必须分别命名、分别测试。

单词允许换行（与单词本一致）；释义固定单行，因此网格在常见数据下保持一致高度。

## 5. 检索区

### 5.1 等级筛选

- 五个选项：全部、初中、高中、四级、六级；顺序取自 `VocabularyLevel.allCases` 的声明顺序。
- 未选中：`palette.secondaryText`，16pt。
- 选中：`palette.accent(for: space)`，16pt semibold，下方一条 2pt 短横线，宽度与文字等宽。
- 不使用胶囊填充按钮，避免引入“控件感”和色彩噪音。
- 等级数量来自真实产物：初中 1,603 / 高中 3,677 / 四级 3,849 / 六级 5,407。

### 5.2 搜索

- 左侧放大镜图标（`palette.tertiaryText`），右侧无边框输入框，占位文字“**输入单词、首字母或中文意思**”。
- **输入即查**，不需要回车，也不做防抖（实测查询在毫秒级）。
- 输入变化时**页码重置为第 1 页**，并清除遮盖状态。
- 搜索与等级筛选是**与**关系。

#### 5.2.1 两种检索模式

输入按**是否包含中日韩字符**决定走哪条路，由纯函数 `LexiconSearchMode.mode(for:)` 判定：

| 模式 | 判定 | 查询方式 |
| --- | --- | --- |
| `englishPrefix` | 不含 CJK | 规范化后在 `search_term` 上做范围查询（走索引） |
| `chineseMeaning` | 含 CJK | 在 `chinese_translation` 上做子串匹配 |

**为什么不采用“两种方式同时搜”**：以输入 `v` 为例。若规则是“单词以 v 开头 **或** 释义里含字母 v”，那么除了 `very`、`visit` 这类词，还会命中所有动词——因为每条动词释义都写着 `vt. 放弃`、`vi. 遵守`，里面都含字母 `v`。实测结果：

| 规则 | 命中 |
| --- | --- |
| 只搜单词前缀 `v` | **125 条**（符合预期） |
| 只搜释义含字母 `v` | 3,272 条（其中 2,491 条由 `vt.` / `vi.` 造成） |
| 两者取并集 | **3,353 条，占全部 7,116 条的 47%** |

一个字母搜出近一半词库，结果无法使用。因此改为**二选一**：输入含汉字就搜释义，不含就搜单词。规则简单，结果可预期。

#### 5.2.2 中文释义检索

- 匹配方式：`chinese_translation LIKE '%' || ? || '%'`，使用参数绑定。
- 输入按空白切分为多个词，**所有词都必须命中**（与关系）。例如“放弃 抛弃”只返回同时含有这两个词条的词。
- **不需要索引**：子串匹配本来就用不上 B-tree 索引。

实测性能（在 7,116 条真实产物上，释义总字节仅 **208 KB**）：

| 查询 | 耗时 |
| --- | --- |
| 英文前缀（走索引，对照） | < 1 ms |
| 中文 `%放弃%`（命中 12 条） | 约 1 ms |
| 中文 `%的%`（最坏情况，命中 2,349 条） | 约 1 ms |

**规模上限与升级触发条件**：若将来改用 `full` 模式（76 万条），释义总量约为现在的 100 倍，全表扫描会升到 100–200 ms 量级，届时需要改用 FTS5 虚拟表。当前规模（7,116 条）**明确不需要**，也不引入额外结构。

#### 5.2.3 高亮

- 高亮方式必须与检索模式由**同一个判定函数**决定，否则界面会“说谎”（例如实际是子串匹配却只高亮前缀）。
- `englishPrefix`：高亮单词的匹配前缀。
- `chineseMeaning`：高亮释义中**所有命中的子串**（用 `AttributedString` 标记多个区间）。
- 高亮使用语言空间强调色，其余文字保持 `palette.primaryText`。

### 5.3 结果条数

- 位于标题行右端，格式 `7,116 条`，使用等宽数字（`.monospacedDigit()`），`palette.secondaryText`。
- 搜索时显示命中数量，让“海量”有实感，也帮助判断搜索是否过窄。

## 6. 悬停浮层

### 6.1 内容

浮层自上而下三块，**按需出现**：

| 顺序 | 内容 | 出现条件 | 规格 |
| --- | --- | --- | --- |
| 1 | 音标 | 词条有音标（99.06%） | 22pt，**等宽字体**，`palette.primaryText`，居中 |
| 2 | 完整词性词义 | 完整内容比列表显示的更多时 | 16pt，`palette.secondaryText`，最多 6 行，超出加 `…` |
| 3 | 等级 | **总是显示** | 13pt，`palette.tertiaryText`，格式 `四级 · 六级` |

等级常驻是为了保证浮层永远有内容：否则遇到“无音标且释义不长”的词会什么都不弹，用户会以为功能失效。

### 6.2 触发与定位

| 项目 | 规格 |
| --- | --- |
| 触发范围 | 鼠标进入词块任意位置（收录按钮除外，5.4 加入） |
| 延迟 | 0.35 秒；移出立即消失 |
| 默认位置 | 词块下方 8pt，水平居中 |
| 垂直翻转 | 下方空间不足时改为词块上方 |
| 水平收拢 | 左右越界时平移，保证完整落在窗口内 |
| 层级 | 绘制在滚动容器**之外**的顶层浮层，绝不参与网格排版 |
| 命中 | `allowsHitTesting(false)`，浮层不拦截鼠标 |
| 动画 | 淡入 120ms；`accessibilityReduceMotion` 为真时直接显示 |

实现要点：滚动容器会裁剪子视图，因此浮层不能挂在词块内部。由词块通过 anchor preference 上报自身在统一坐标空间的 frame，页面顶层根据该 frame 计算位置并绘制。

### 6.3 与遮盖的关系

- **遮盖优先**：字段被遮住时，浮层不显示该字段的内容。
- 词性词义被遮住时，浮层只显示音标与等级。
- 音标不参与遮盖（见第 7 节），因此只要词条有音标，它总会出现。

### 6.4 无障碍

悬停是鼠标专属操作，键盘与 VoiceOver 无法触发。因此：

- 词块的辅助功能标签**始终包含完整释义与音标**，不依赖浮层。
- 键盘聚焦词块时同样弹出浮层。
- 浮层本身不作为独立的可聚焦元素，避免读屏重复朗读。

## 7. 遮盖

- 与单词本**完全一致**：点击单词切换单词遮盖，点击词性词义切换释义遮盖。
- 遮盖块沿用 `palette.panelRaised` 填充 + `palette.border.opacity(0.8)` 描边 + 圆角 6，尺寸与原文字占位一致，切换时**不改变网格布局**。
- **音标不参与遮盖**：音标只是读音辅助，遮住它没有记忆意义，而且它默认就不显示（在浮层里）。因此可遮盖字段只有两个，与单词本的字段数一致。
- 以下操作清除当前页的遮盖状态：翻页、切换等级、修改搜索词、重新加载数据。
- 右下角提供悬浮的“刷新”按钮，用于清除当前页遮盖；其位置为滚动内容预留底部空间。
- 单词本还有“眼睛”循环按钮，词库**暂不做**：词库以检索为主，整页循环遮盖的使用频率低，保留右下角刷新即可。该取舍列为待确认项。

## 8. 分页与滚动

- 每页 **50 条**（`LexiconQuery.pageSize` 由 20 改为 50），7,116 条为 **143 页**。
- 词条区滚动，检索区与分页区固定。
- 底部居中显示 `‹ 第 1 / 143 页 · 1–50 条 ›`，数字使用等宽数字。
- 首页禁用上一页，末页禁用下一页。
- 翻页后滚动位置回到顶部。
- 改变等级或搜索词后回到第 1 页。

> 此处**修正**了《词库实现设计》第 8 节原先“沿用单词本每页 20 条”的决定：按 20 条计算需要 356 页，翻页不现实。该修正需要同步更新 5.2 的 `pageSize` 常量与相关分页测试。

## 10. 无障碍标识

| 元素 | identifier |
| --- | --- |
| 页面 | `workspace.lexicon` |
| 等级筛选（全部） | `lexicon.filter.all` |
| 等级筛选（各等级） | `lexicon.filter.<level.rawValue>` |
| 搜索框 | `lexicon.search` |
| 结果条数 | `lexicon.resultCount` |
| 词块 | `lexicon.entry.<uuid>` |
| 词块的单词 | `lexicon.entry.<uuid>.word` |
| 词块的词性词义 | `lexicon.entry.<uuid>.meaning` |
| 上一页 / 下一页 | `lexicon.pagination.previous` / `.next` |
| 页码状态 | `lexicon.pagination.status` |
| 清除遮盖 | `lexicon.mask.reset` |
| 空状态 | `lexicon.empty` |

- 词块的辅助功能标签始终为“单词 + 完整词性词义 + 音标（若有）”，遮盖状态只改变可见性，不删除语义。
- 等级筛选暴露为可选择的按钮并标注“已选择 / 未选择”，与工作区功能栏的做法一致。

## 11. 空状态与错误

| 场景 | 行为 |
| --- | --- |
| 搜索无结果 | 显示“没有匹配「xxx」的单词或释义”，并提供清除搜索的操作 |
| 某等级无数据 | 显示该等级暂无词条（正常数据下不会出现） |
| 词库资源缺失 | 显示“词库数据缺失，暂时无法浏览词库”，浏览与搜索禁用；个人单词本不受影响 |
| 词库版本不兼容 | 显示明确错误，不尝试查询未知结构 |
| 查询失败 | 显示可理解的错误，不静默显示为空列表 |

## 12. 测试与验收

### 12.1 单元测试

- 等级切换后结果条数与产物基线一致（1603 / 3677 / 3849 / 5407）。
- 搜索输入变化后页码重置为 1，遮盖状态被清除。
- 检索模式判定：含 CJK 走中文模式，纯 ASCII 走英文前缀模式；判定函数与高亮方式使用同一个来源。
- 中文检索：单字命中（如“放弃”命中 `abandon`）、多词与关系（“放弃 抛弃”）、无命中返回空页。
- 中文检索与等级筛选叠加时结果正确。
- 无结果时 `pageCount` 为 0，不显示“第 1 / 1 页”。
- 分页在 0、1、50、51、100、101 条下的边界正确。
- 浏览级短释义：保留词性前缀、取首个词性组、16 字符截断、无词性前缀时的回退。
- 浮层内容组装：有音标 / 无音标、释义是否比列表更长、等级顺序。

### 12.2 界面验收

- 英语空间进入“学习资料”显示词库；日语空间仍显示占位。
- 双栏等高网格，释义单行截断，长单词只在自己的半列内换行。
- 五个等级筛选切换后内容与条数正确，选中项有强调色下划线。
- 输入完整单词与首字母均能命中，前缀高亮显示；输入中文（如“放弃”）能命中对应词条，命中子串高亮；清空后回到等级浏览。
- 遮盖单词或释义后布局不跳动，刷新按钮清除当前页遮盖，翻页后遮盖自动清除。
- 悬停 0.35 秒后浮层出现，内容为音标 + 完整释义 + 等级；词义被遮时浮层不显示词义。
- 靠近窗口底部与右侧的词块，浮层自动翻转/收拢，不溢出窗口。
- `820 × 560` 最小窗口与深浅两套主题下，检索区、网格、分页均可用且不遮挡。
- 减少动态效果开启时浮层直接显示，无淡入。

## 13. 5.3 与 5.4 的边界

| 能力 | 阶段 |
| --- | --- |
| 等级浏览、搜索、分页、遮盖、悬停浮层 | 5.3（已完成） |
| 收录按钮（悬停显形）、已收录浅黄标记、来源枚举迁移、不污染高频词 | 5.4（已完成） |

5.3 完成时词库可看、可搜、可遮，但**没有收录入口**。这样 5.4 的数据迁移可以单独提交、单独测试。

同时 5.3 需要把查询层接入组合根：在 `AppDependencies` 中创建 `SQLiteLexiconRepository`，失败时降级为 `UnavailableLexiconRepository`，与现有仓储的降级方式一致。

## 17. 词库体验修正（5.3.1，2026-09-11）

5.3 与 5.4 上线后经过实际使用，发现五处体验问题。本节记录修正结果，**与第 3、4、5 节冲突时以本节为准**。

### 17.1 词块改回左右两栏

原来的"单词在上、词性词义在下"让页面中间大片留白、横向显得很空。改为：

```text
   abandon            vt. 放弃, 抛弃…        abide          vi. 遵守, 持续…
```

- 用 `EntryFieldsLayout`（原 `EqualFieldsLayout`，从单词本提取出的共用组件）排布，默认样式下单词与词性词义各占词块的一半。
- 网格每行两个词条，合起来就是单词本那样的**四等分横向排布**。
- 复用同一个布局组件而不是复制一份，避免两个页面的排布规则日后各自漂移。

### 17.2 检索区

- 等级顺序改为**由高到低**：全部 / 六级 / 四级 / 高中 / 初中。
  `VocabularyLevel` 的声明顺序同时决定筛选条顺序与词条的等级标注顺序，只有一套次序。
- 检索区收窄到居中的一条带（最大 720pt），筛选与搜索框彼此靠近，不再被拉到窗口两端。
- 上下分隔线改为**中间粗、两端细并淡出**：自绘 `LexiconTaperedRule` 形状叠加水平渐变遮罩。

### 17.3 浏览顺序与洗牌

**问题**：词频排序让每次打开词库都从同一批最基础的词开始，枯燥且增加阻力。

**方案**：浏览时按种子洗牌；搜索时保持词频顺序（搜索是定向的，稳定顺序更有用）。

| 项目 | 规则 |
| --- | --- |
| 排序键 | `加权系数 × (((id + 种子) × 2654435761) % 1000000007)`，并列时按 `search_term` |
| 四六级加权 | "全部"视图下四级/六级系数 1、其余 3，**倾向于靠前但不挤占** |
| 洗牌时机 | 距上次洗牌超过 **15 分钟**再次进入词库时自动换一批；同一次使用期间保持不变 |
| 手动换 | 标题栏右侧「换一批」按钮；搜索时隐藏（此时顺序由词频决定，换了也看不出） |

**为什么不用 `ORDER BY RANDOM()`**：那样第 1 页与第 2 页会重叠，而且每次翻页结果都变。种子固定时整批顺序稳定、分页不重不漏（已有测试逐一比对 143 页的 ID 集合）。

**为什么加权用乘系数而不是分区**：把四六级全部排在前面会让初高中独有的约 1,700 个词永远落在 100 页之后；乘系数只是拉大其它词的排序键，仍然混排。

**为什么保留 15 分钟冷却**：纯"每次进入都换"会让用户去单词本查个词再回来就找不到刚才的词，反而增加阻力。

### 17.4 遮盖贴合文字

原来遮罩铺满整个字段，看起来像一条黑条。根因是 `frame(maxWidth: .infinity)` 放在遮罩**之前**，遮罩因此覆盖了撑开后的宽度。修正为：遮罩贴在文字自身上，最后才用 `frame` 撑开占位（与单词本一致）。

同时把浏览级短释义由 16 字收紧到 **12 字**：词块由"占半窗宽"变为"占四分之一窗宽"后放不下 16 字。截断点落在分隔符上时会先去掉尾随标点再补省略号。

### 17.5 收录写入短释义

收录到单词本时写入**浏览级短释义**（例如 `n. 节目, 节目单…`），而不是完整的多行释义——后者会让单词本里一个词占七八行。

代价是丢失后面的义项。这是可接受的：词库随时能查到完整释义，单词本只承担"提醒"作用，而且单词本里的词义本来就可以手动编辑。

## 18. 词库二次体验修正（5.3.2，2026-09-11）

第二轮实际使用反馈的修正结果。**与前面各节冲突时以本节为准。**

### 18.1 网格整体错位一行（缺陷）

现象：左列第一个格位是空的，左列比右列多出一个，整列像被下移了一格。

根因：滚动回顶部的锚点 `Color.clear.frame(height: 0).id(topAnchorID)` 被放在了 `LazyVGrid` 的**第一个子视图**位置，占掉了第一个格位。

修正：把锚点移到网格**外面**（外包一层 `VStack`），网格不再被顶掉一格。

### 18.2 筛选与搜索不在同一基线上

原来等级按钮用 `VStack { 文字; 下划线 }`，下划线参与布局高度，把文字整体抬高，与搜索框的文字错开。

修正：下划线改为 `overlay(alignment: .bottom)` + `offset`，**不参与布局**，两处文字因此落在同一基线上。

### 18.3 收藏按钮与词条同一行

原来按钮绝对定位在词块右上角，视觉上浮在词条上方。改为词块内的第三列：

```text
   abandon          vt. 放弃, 抛弃…   ⊕      abide        vi. 遵守, 持续…   ⊕
```

- 按钮与词条垂直居中，宽度固定（26pt）并**常驻占位**，显隐时不推动词条。
- 不可见时 `allowsHitTesting(false)`，不会挡住单词的遮盖点击。
- 三种状态的图标与文案：未收藏 `plus.circle` / 已收藏 `checkmark.circle.fill` / 来自文档导入 `checkmark.circle`。
- 词在单词本中（无论来源）时，单词文字使用同一个标记色。

### 18.4 悬停浮层

- **只有悬浮在「词性词义」字段上才触发**。原来整个词块都触发，光标移过就容易误弹。
- 延时由 0.35 秒延长到 **0.6 秒**。
- 淡入时长由 120ms 放宽到 **250ms**，并叠加轻微上浮，观感更柔和。

### 18.5 收藏 / 取消收藏

按钮是开关：点击收藏，再点取消。取消的规则见 [ADR-003](../architecture/架构决策-003-公共词库与个人单词本分离.md) 决策 4 与《词库实现设计》第 5.4 节，核心是**绝不删除文档导入与手动新增的内容**。

三种状态下的点击行为：

| 状态 | 点击结果 |
| --- | --- |
| 不在单词本 | 收藏，写入当日记录 |
| 已收藏 | 取消收藏；词条只来自收藏则整体删除，另有来源则只移除收藏记录并提示 |
| 来自文档导入／手动新增 | 不删除任何内容，提示到单词本中管理 |

### 18.6 收藏计入当日

收藏现在会写入当天的出现记录，因此**当天的日期分组会包含今天收藏的词**。
详见 ADR-003 决策 4（该决策已于 2026-09-11 修订）。

## 19. 浮层缺陷修复（5.3.3，2026-09-11）

使用中发现悬停浮层有两个缺陷，均已定位到根因并修复。

### 19.1 首次进入词库时浮层不出现

**现象**：刚进入词库时把光标停在「词性词义」上不弹浮层；点一下分类或遮盖之后才恢复正常。

**根因**：`clearHover()` 把 `cellFrames` 与 `tooltipSize` 一起清空了。这两个值来自偏好上报，属于**布局结果**而不是悬停状态：

- 首次进入时 `store.page` 变化会触发 `clearHover()`；
- 此时网格已经把每个词块的位置上报完毕，清空之后**偏好值本身没有变化**，`onPreferenceChange` 不会再次触发；
- 于是 `cellFrames` 一直为空，浮层定位守卫 `cellFrames[entry.id]` 永远失败。

点分类或遮盖会让网格重建、位置重新上报，所以看起来"互动一下就好了"。

**修正**：`clearHover()` 只清理悬停状态，不再触碰布局缓存。网格每次布局都会重新上报完整的位置字典，不需要也不应该手工清空。

### 19.2 淡入突兀

**根因**：透明度直接由测量结果决定（`opacity(tooltipSize == .zero ? 0 : 1)`），而动画只监听 `hoveredEntryID`。测量完成导致的透明度变化**不在任何动画的时间范围内**，因此是从 0 直接跳到 1。

**修正**：把"测量"和"显示"拆成两步，并让淡入淡出由**同一个状态**驱动：

1. 悬停延时结束后，先以透明状态渲染一帧完成尺寸测量；
2. 测量回调里用 `withAnimation` 把 `isTooltipShown` 置为真，产生真正的淡入；
3. 离开时先淡出，动画结束后再卸载浮层，避免"边淡出边被移除"的生硬收尾。

不再叠加 `transition`：透明度被过渡与修饰符两套动画相乘会让观感不可控。淡入时长 0.25 → **0.28 秒**。

### 19.3 可悬停区域

字段内容居中，文字较短时只有文字笔画附近才算命中。为字段补上 `contentShape(.rect)`，整个字段区域都可点击、可悬停。

### 19.4 无障碍补齐

浮层对读屏是隐藏的（避免与词块重复朗读），但这样一来**音标在任何地方都读不到**。已在「词性词义」字段的无障碍标签中补上完整释义与音标：

- 视觉：短释义 + 音标只在浮层里；
- 读屏：词块直接读出完整释义与音标，不依赖鼠标悬停。

## 20. 第三轮调整（5.3.4，2026-09-11）

### 20.1 已收藏单词的字体颜色（缺陷）

现象：收藏后只有按钮变黄，单词本身仍是默认色。

根因：`maskedField` 把 `.foregroundStyle(color)` 加在了**隐形的尺寸占位副本**上，而可见副本在 `.overlay` 里。
`foregroundStyle` 是环境值，**不会传播到后加的 overlay 内容**，因此可见文字一直用默认颜色。

修正：可见副本自己上色。这也顺带解释了为什么"释义"字段的颜色错误一直没被发现——它的颜色恰好与默认色相同。

### 20.2 浮层显示收藏状态与日期

浮层新增一行：`已收藏 · 2026年09月11日`（多日收藏用顿号连接），使用与收藏按钮相同的标记色。

为此仓储的收藏查询由"只返回状态"扩展为返回 `LexiconCollectionInfo`（状态 + 收藏日期，日期倒序）。

### 20.3 顶部功能栏改名与换位

- 「学习资料」改名为「**词库**」。
- 顺序由 `单词本 / 单词刷 / 学习资料` 改为 `单词本 / **词库** / 单词刷`。
- 枚举 `WorkspaceFeature.documents` 一并重命名为 `.lexicon`，标识符同步改为 `workspace.lexicon.*`。
  留着 `.documents` 而界面写着"词库"，正是此前一直在清理的文档与代码漂移。
- 顺带移除 UI 测试里一个**没有调用点**的旧卡片网格断言（早期功能卡片页的遗留，其几何假设早已失效）。

### 20.4 单词本的盲盒

单词本的「默认分页」也接入洗牌：与词库同样使用**15 分钟冷却 + 手动「换一批」**，但**两个功能各自持有独立控制器**，互不影响对方的浏览顺序。

- 按日期浏览是分组视图，不参与洗牌。
- 洗牌在内存中完成（单词本数据量小），使用 FNV-1a 从词条 UUID 与种子派生排序键。

> **实现中发现的缺陷**：第一版写作 `hash ^ seed`。XOR 只翻转种子里为 1 的位，排序键的高位几乎不变，
> 结果是"换了种子但顺序几乎没变"，等于没洗牌——正是《阶段 5.3.1》在词库那边踩过的同一类错误。
> 现在种子会先经过完整的一轮 FNV 散列再参与排序，并由测试锁定"换种子必须换一批顺序"。
