## 6. `translation` 的真实形态

| 指标 | 值 |
| --- | --- |
| 含**字面** `\n`（反斜杠 + n） | 5,330（74.90%） |
| 含**真实**换行符 | **0** |
| 含字面 `\r` | 1 |
| 首行带词性前缀 | 7,089（**99.62%**） |
| 整条以 `[` 开头（`[计]`、`[古]` 等领域标注） | 13 |
| 长度（字符）：最小 / p50 / p90 / p99 / 最大 | 2 / 27 / 55 / 100 / 196 |

> 注：上表长度按源文件**原文**统计（字面 `\n` 占两个字符）。构建期还原为真实换行后长度略短：实测 p50=26、p90=53、p99=96、最长 191。差异仅来自换行还原，不影响结论。

关键结论：

1. **换行是转义序列，不是真实换行**。ECDICT 用字面 `\n` 表示换行，`\r` 同理。构建期必须做一次确定的还原（`\n` → 换行），否则界面上会显示成 `\n` 字样。
2. **词性信息自带在 `translation` 中**，99.62% 的词条首行以 `a.` / `n.` / `v.` / `vt.` / `adv.` 等前缀开头。这验证了"词性词义取 `translation`"的设计决定。
3. 不带头缀的 27 条是 `a`、`AM`、`are`、`antisocial`、`attent` 这类特例，其中部分首行是语法说明（如 `be 的单数第一人称`），派生简短释义时必须能容忍。
4. 释义**不止是词性 + 词义**：还可能包含 `[计]` 等领域标注、以及 `run的过去式和过去分词` 这类语法说明行。简短释义的派生规则必须跳过这些行。最长 196 字符、p90 已达 55 字符，远超单词刷选项按钮的可用宽度，**简短释义派生是必需项，不是优化项**。

最长样例（`round`，196 字符）：

```text
n. 圆, 圆形物, 巡回, 循环, 一轮, 一回合, 一局, 范围, 轮唱\na. 圆的, 球形的, ...
```

## 7. 体积

| 项目 | 值 |
| --- | --- |
| 词形 + 搜索键 + 音标 + 中文释义 + 等级关系 + 行与索引开销（字节估算） | 约 1,124,501 字节 |
| 字节估算产物大小 | 约 1.07 MB |
| **实测产物大小**（5.1 构建产出） | **2,617,344 字节 ≈ 2.5 MB** |

字节估算低估了约 2.3 倍，原因是它没有计入 SQLite 的页对齐、B-tree 与索引开销。**实测 2.5 MB 仍然很小**——比《词库实现设计》第 8 节最初按“最多 2 万条”估算的 4–8 MB 还小；即使扩展到全部 8 个等级（14,942 条），按同比例预计约 5 MB。**本地打包的方案得到数据支持，完全没有上服务端的必要。**

## 9. 尚未验证的事项

1. **跨语言规范化一致性**：Python `str.lower()` 与 Swift `lowercased(with: en_US_POSIX)` 是否在所有相关字符上一致。已准备 18 条固定样例（`tools/lexicon-builder/fixtures/normalization-cases.json`），Python 侧已通过；Swift 侧断言要等 5.2。
2. ~~**真实 SQLite 体积**~~：已由 5.1 构建核实为 2,617,344 字节（2.5 MB）。
3. **界面布局**：还原后 p90 长度 53 字符、最长 191 字符的释义在词库列表与单词刷选项中的实际排版表现，需要 5.3 阶段用真实数据验收。
4. **词形变体**：ECDICT 提供隐藏字段 `sw`（去除所有非字母数字并小写）用于模糊匹配。首版 `search_term` 采用较温和的规范化（折叠空白 + 小写），是否需要额外引入 `sw` 式变体匹配，留待 5.2 评估。
5. **`stardict.7z` 中更完整的数据**（含非空 `pos`）是否需要，本阶段明确**不采用**。

## 10. 结论

勘察与随后的 5.1 构建均已完成。数据质量足以支撑首版：

- 目标子集零重复、零碰撞，中文释义完整，构建期拒绝行数为 0；
- 音标缺失率 0.94%，可接受；
- 词性信息可从 `translation` 前缀稳定获得；
- 产物实测 2.5 MB，完全适合随 App 打包；
- 相同输入两次构建字节一致（可复现）。

产品规模已确认：维持四等级 **7,116 条**。扩展路径（全部 8 个标签共 14,942 条）暂不采用，将来只需调整等级映射并重建，schema 无需改动。
