## 0. v2 修订说明（2026-09-13，用户实测反馈）

初版把入口放在**词库页**（标题栏「开始单词刷」），并为此建了一套跨工作区传范围的机制。
用户实测后提出两条调整，本版据此返工：

| # | 用户反馈 | 本版做法 |
| --- | --- | --- |
| 1 | 不该在词库单独开一个入口，应该在**单词刷里把词库作为一种考核范围** | 范围选择器变成 默认 / 日期 / **词库** 三项；撤掉词库页入口与整套跨工作区传参机制 |
| 2 | 考词库的词时，答案**不仅要有词义，还要有词性** | 词库候选的选项文本由 `shortGloss` 改为 `browsingDisplay`（保留 `vt.` / `n.` 前缀） |

**副产品**：第 2 条顺带解决了 5.5 记录的"同一个词在两条链路上释义文本不同"——现在词库选项与
单词本里收藏的释义都是 `browsingDisplay`，形态一致。

## 1. 目标与范围

在单词刷里把**公共词库**作为第三种考核范围：选「词库」即考词库的单词，并可再选具体等级。

包含：

1. `WordQuizRangeMode` 新增 `.lexicon`；选中后显示等级选择器（全部 / 六级 / 四级 / 高中 / 初中）。
2. 新增词库范围 `WordQuizScope.lexicon(LexiconQuizScope)`，与既有 `allImported` / `date` 并存。
3. 词库候选直接来自只读查询层，**不写 SwiftData**：未收藏的词条也能被考。
4. 词库范围的选项文本**带词性**。

不包含：

- 词库页的速测入口（v2 已撤销）。
- 混合范围（词库 + 个人词条）。
- 词库范围下的关键词搜索：单词刷页没有搜索框，筛选只按等级。
- 新的视觉体系：范围与等级选择沿用设置区现有的 `Picker` 范式。

## 2. 5.5 遗留的三个约束与解法

[词库与单词刷联动实现设计](词库与单词刷联动实现设计.md) 第 3.4 节记录了三个结构性约束。逐条解法：

### 2.1 `WordQuizScope` 装不下 `[LexiconEntry]`

**不把候选集放进 scope**。`WordQuizScope` 表达的是"这次考什么"，它必须是可 `Hashable, Sendable`
的**筛选描述**，而不是数据本身——数据由候选源在启动时按描述加载。

```swift
enum LexiconQuizScope: Hashable, Sendable {
    case all                     // 全部等级
    case level(VocabularyLevel)  // 某一个等级
}

enum WordQuizScope: Hashable, Sendable {
    case allImported
    case date(VocabularyDocumentDate)
    case lexicon(LexiconQuizScope)
}
```

初版这里是带 `keyword` 的结构体（对应词库页的搜索筛选）。v2 撤销了词库页入口，
单词刷页也没有搜索框，因此**收窄为只有等级**——按《开发规范》"不为未来假设提前引入抽象"，
不留没有人会设置的字段。查询层与测试里仍保留关键词检索能力，将来若要在单词刷里支持搜索，
只需给这个枚举加一个分支。

### 2.2 干扰项池应当来自整个词库

**已确认（2026-09-13）：按范围各自取池。** 词库范围用**整个词库 7,116 条**作干扰项池，
单词本范围继续用个人词条的既有池。两个池子各自内部文本形式统一，不混用（理由见 2.5）。

因此 `WordQuizCandidateSource` 需要一次"读全库"的能力，而 `LexiconQuery.pageSize` 固定 50 条、
翻完需要 143 页。**`LexiconRepository` 协议新增一个不分页入口**：

```swift
/// 一次返回整个筛选结果，供单词刷抽题使用。
/// 分页是词库列表的界面约束，不是查询层的语义上限。
func entries(matching query: LexiconQuery) throws -> [LexiconEntry]
```

WHERE 子句必须与分页查询**共用**同一个构造函数，否则两条路径会随迭代漂移出不同语义。

### 2.3 ~~跨工作区请求通道~~（v2 已删除）

初版为了"从词库页发起"，在 `ContentView` 加了一个 `@State` 保存待考范围，并配了一条
"导航时何时清空该范围"的规则（写成 `nonisolated` 纯函数以便单测）。

**v2 全部删除**：范围改由单词刷页自己的范围选择器决定，不存在跨页面传参，
那条"清空时机"规则连同它的测试一起作废。这也顺带消除了初版最危险的一个缺陷来源——
该规则写反时会让用户被永久锁在某个等级范围里，而设置区当时是只读的。

**仍然不新增 `AppRoute` 枚举分支**：理由不变，`AppRoute` 被 `FocusedValue`（快捷键命令）与
`synchronizeStudyTime` 共用，为一次导航扩大取值面会波及快捷键、计时与既有路由测试。

### 2.4 释义派生：词库范围必须真正派生，并保留词性

5.5 给引擎加了"显示文本不得撞车"的闸门，但**引擎看到的仍是候选自带的 `meaning`**。
词库词条自带的 `gloss` 是完整释义（中位 27 字、p90 55、最长 196），直接放进 136 × 78 的选项按钮必然溢出，
而"显示文本"在引擎里只是折叠空白。因此在**候选源**处就派生：

```swift
WordQuizCandidate(
    id: entry.id,
    term: entry.term,
    meaning: LexiconGlossFormatter.browsingDisplay(from: entry.gloss).text
)
```

- 用 `browsingDisplay`（**保留词性前缀**、12 字上限）：用户明确要求"考词库的词时答案不仅要有词义，还要有词性"，
  而词性正来自词库独有的这个前缀（个人单词本没有这个概念）。
- v1 曾用 `shortGloss`（去前缀）。改回来还有额外好处：它与"收藏进单词本时写入的释义"完全一致，
  两个池子不再有两种文本形态（见 2.5）。
- 派生后长度 ≤ 13（12 字 + 省略号），适配既有按钮尺寸，不新增常量。
- 词性覆盖率实测：四级 3,849 条中带合格词性前缀的超过 3,809 条（少数无前缀是词典事实），由测试锁定。
- 截断造成的显示冲突由 5.5 的闸门兜住。

### 2.5 两个池子的文本形态（v2 后已一致）

两个池子仍然分开保存与取用（目标集必须来自筛选范围，干扰项池来自全库），但**文本形态已经统一**：
v2 起词库候选也用 `browsingDisplay`，与"收藏进单词本时写入的释义"完全相同。

因此现在同一个词无论是"词库范围里直接考"还是"收藏后从单词本考"，选项文本一模一样
（都是 `vt. 放弃, 抛弃…`）。5.5 记录的"同一词两种释义文本"这一评估项据此关闭。

## 4. 行为规格

1. **范围选择器三项**：默认 / 日期 / 词库。选中「词库」后，日期选择器的位置换成**等级选择器**（全部 + 四个等级，默认「全部」）。
2. **等级与范围一样受答题保护**：答题进行中不允许换范围或换等级（`settingsAreLocked` 已统一拦截）。
3. **加载时机**：进入单词刷页时读一次词库候选（备好供用户随时切过去）；改等级立即重读；答题中不读。
4. **候选不足**：目标词条为空或不同词义不足 4 个时给出**范围相关**的提示，不说"请先导入单词"。
5. **读取失败**：保留仓储的失败原因（如"词库数据缺失"），不被"范围没有词条"覆盖。
6. **不写数据**：整个流程不产生任何 SwiftData 写入（ADR-003 决策 2）；未收藏的词条也能考。
7. **选项文本带词性**：词库范围下四个选项都形如 `n. 苹果, 家伙…`，与词库列表、单词本里显示的形态一致。

## 5. 测试计划

单元测试：

1. `entries(matching:)`：各等级数量与勘察基线一致（初中 1,603 / 高中 3,677 / 四级 3,849 / 六级 5,407）、
   与分页查询结果**逐条一致**（同一查询两种读法必须等价）、关键词搜索命中、空结果。
2. `LexiconQuizCandidateSource`：目标集来自筛选、id 与 term 与词库一致、释义已派生
   （不含换行、长度 ≤ 13）、干扰项池是整个词库（不是筛选子集）、错误原样抛出。
3. `WordQuizStore`：`startLexiconQuiz` 后 `allCandidates` 为空也能加载词库候选；
   范围文案；词库范围下候选不足的提示；词库范围不影响单词本范围的加载结果。
4. `WordQuizEngine`：词库候选（派生后文本）能正常组卷，四选一且选项显示文本互不相同——回归 5.5 的闸门。

界面测试：词库页可见并可用「开始单词刷」；点击后进入单词刷页且范围文案为词库范围；未开始时不会自动出题。

## 6. 不采用的方案

| 方案 | 不采用原因 |
| --- | --- |
| 把 `[LexiconEntry]` 放进 `WordQuizScope` | scope 是筛选描述而非数据载体；`LexiconEntry` 也不满足 `Hashable` |
| 新增 `AppRoute` 分支携带范围 | 会波及 `FocusedValue` 快捷键、`synchronizeStudyTime` 与路由测试 |
| 词库范围也把收藏词并进目标/干扰池 | 同一词两套文本形式，选项风格不一致；且收藏只是个人副本 |
| 用 `browsingDisplay` 做选项文本 | 保留 `vt.` 前缀并带省略号，是列表展示需求；选项池必须统一且尽量短 |
| 复用 `allImportedCandidates` 的文案 | 词库范围与"导入"无关，文案会误导 |

## 7. 风险

| # | 风险 | 处理 |
| --- | --- | --- |
| 1 | 不分页入口与分页入口语义漂移 | WHERE 子句共用构造 + 逐条一致性测试 |
| 2 | 词库范围每次进入要读 7,116 条 | 实测全表扫描 1–2 ms；只在范围变化或页面进入时读一次，不在打字/答题时读 |
| 3 | 两套候选源（单词本 / 词库）在同一 Store 内互相污染 | 按范围分支取池，并用测试锁定"词库范围不影响单词本范围" |
| 4 | ~~从词库发起时已有未完成答题~~ | **v2 已消除**：范围只在单词刷页内选择，答题进行中该控件整体禁用 |
| 5 | 搜索结果太少凑不出四选一 | 既有校验会明确失败；提示文案按范围区分，不误导成"需要导入单词" |

## 8. 验收记录

### 8.1 v2（2026-09-13，返工后重新验收）

单元测试 **237 个用例全部通过**，Debug 构建成功。与 v1 相比：删掉作废的导航测试文件（5 条）与
词库页入口的界面测试（2 条），新增/改写范围模式与词性相关用例。

新增与改写覆盖：

- 范围模式：选「词库」后默认考全部等级（scope = `.lexicon(.all)`）；选等级后 scope = `.lexicon(.level(.cet4))`；
- **词性**：候选释义等于 `browsingDisplay` 结果、以 `n.` 开头、长度 ≤ 13；四级 3,849 条中
  带合格词性前缀的不少于 3,809 条；
- 范围隔离：词库范围在个人单词本为空时仍可考；切回单词本范围后目标集与判据都不受词库池影响；
- 空范围与读取失败给出**不同**提示（后者保留仓储失败原因）；
- **答题保护**：进行中改范围或改等级都不生效；
- 真实词库端到端：四级 3,849 条候选、7,116 条池，被抽中的词必属四级，四选一且显示文本互不相同。

界面测试新增 1 条：范围选择器有 3 项、默认范围下无等级选择器、选词库后出现等级选择器、
开始按钮可用（证明未收藏的词也能考）、开考后四个选项都带词性。

### 8.2 v1（2026-09-13，已被 v2 取代）

v1 把入口放在词库页并实现了跨工作区传范围。用户实测后要求改为"在单词刷里选词库范围"，
故入口、`ContentView` 的范围状态与"导航时清空范围"的规则全部删除。v1 记录在案的三处自查缺陷中，
第 1 条（导航清空规则写反）与本次返工直接相关——**那条规则连同它的风险面一起被删掉了**，
风险 4 相应关闭。第 2、3 条（失败原因被覆盖、空范围提示文案）在 v2 中仍然适用并保留测试。
