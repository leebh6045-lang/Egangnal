- 状态：设计评审通过（2026-09-11）；数据勘察进行中，尚未开始编码

- 关联文档：[ADR-003：公共词库与个人单词本分离](../architecture/架构决策-003-公共词库与个人单词本分离.md)；[词库界面设计](词库界面设计.md)；[ECDICT 离线词库构建契约](ECDICT离线词库构建契约.md)；[ECDICT 数据勘察报告](ECDICT数据勘察报告.md)；[ECDICT 接入保姆级教程](../ECDICT接入保姆级教程.md)；[WordNet 接入保姆级教程](../WordNet接入保姆级教程.md)

## 1. 目标与范围

### 1.1 目标

在“学习资料”下实现**词库**：一个只读的、内置分级的英语词汇目录，用于浏览、检索和记忆，并作为个人单词本的“进货渠道”。

### 1.2 本阶段包含

- 内置英语词库，按**初中、高中、四级、六级**四个等级浏览与筛选。
- 每个词条的显示形态：**单词 · 音标 · 词性词义**。
- 词性词义的**遮盖**（辅助自我测试），行为对齐单词本的遮盖能力。
- **搜索**：支持完整单词与首字母（前缀）检索。
- **收录**：把词条写入个人单词本，仅收录**单词 + 词性词义**，不收录其他字段。
- 在英语语言空间的“学习资料”中呈现；日语空间的“学习资料”保持现状占位。

### 1.3 本阶段不包含

- 日语词库（数据源、分级和排序规则都未确定）。
- 用户自己的 `.md` / `.txt` 资料导入与只读阅读（原路线图“只读资料空间”内容，见第 13 节与路线图 5.6）。
- 多义项结构化拆解、英文释义展示、例句、词源、同义词与语义关系（WordNet 相关内容后置）。
- 发音音频、在线释义、在线翻译。
- 复习算法、掌握度、答题历史、学习计划。
- 词库的云端同步或热更新。

### 1.4 与现有功能的关系

| 现有能力 | 本阶段如何处理 |
| --- | --- |
| `WorkspaceFeature.documents`（“学习资料”） | 保留该入口，其页面由占位替换为词库 |
| `WordBookRepository` / `WordEntry` | 作为“收录”的写入目标，仅新增来源标记 |
| `WordOccurrence` / 高频词 | **不改语义**，收藏不产生出现记录 |
| `WordQuizEngine` | 领域契约**不改**（题目结构 / 评分 / 错题重做 / 难度分支）；5.5 仅在干扰项挑选中多加一道"显示文本不得撞车"的闸门，见 6.2 |
| `WordQuizCandidateSource` / `WordQuizScope` | **5.5 核实后无需改动**（收藏词早已有出现记录，本就在默认抽题池）；等级速测若重新立项再扩展，详见第 6 节 |
| `AppTheme` / 分页与遮盖范式 | 直接复用，不新增视觉体系 |

## 2. 核心概念与术语

- **公共词库**：随 App 打包、只读、可整体替换的英语词汇目录（`EgangnalLexicon.sqlite`）。
- **词条**：词库中的一条记录，例如 `abandon`。
- **词性词义**：一个词的词性前缀与中文释义的组合展示文本，例如 `v. 放弃；抛弃`。本阶段**不拆分为多个义项**。
- **收录**：用户把某个词条写入个人单词本的动作；结果是一条 `WordEntry`。
- **等级**：`初中` / `高中` / `四级` / `六级`，对应数据源标签，映射见《ECDICT 离线词库构建契约》第 4 节。

## 3. 词条显示形态与字段映射

需求约定的词条显示形态为“单词 音标 词性词义”，三者**同属一条记录**。数据源字段到展示的映射如下：

| 展示位置 | 词库列 | 来源（ECDICT） | 说明 |
| --- | --- | --- | --- |
| 单词 | `term` | `word` | 原始展示词形 |
| 音标 | `phonetic` | `phonetic` | 允许为空，缺失时不显示占位符（勘察缺失率 0.94%） |
| 词性词义 | `chinese_translation` | `translation` | **原样展示**，99.62% 的首行自带 `a.` / `n.` / `v.` 等词性前缀 |
| （不入库） | — | `definition` | 首版不展示故不保留（勘察：目标子集 99.76% 有值，将来可加列） |
| （不入库） | — | `pos` | 勘察确认 `ecdict.csv` 中该列 **100% 为空**，不可用 |

**关于 `pos` 字段**：勘察已给出确定结论。ECDICT README 说明 `pos` 是**语料库词性占比**（例如 `n:46/v:54`），本身不能作为界面文本；而基础版 `ecdict.csv` 中该列**完全为空**。因此“词性词义”一律取 `translation` 前缀，schema 中不保留 `pos` 列。

**关于换行**：源文件用**字面 `\n`**（反斜杠 + n）表示换行，勘察确认不存在真实换行符（74.90% 的词条含此转义）。构建期做一次确定的还原（`\n` → 真实换行），界面上不得出现 `\n` 字样。

**多行与超长释义**：`translation` 包含换行、多个义项、`[计]` 领域标注，甚至 `run的过去式和过去分词` 这类语法说明行。长度中位 27 字符、p90 达 55、最长 196。浏览列表允许换行展示；但单词刷的选项按钮尺寸固定（`AppTheme.wordQuizChoiceWidth` × `wordQuizChoiceHeight`），长释义必然溢出，因此**测验用简短释义的派生是必需项，不是优化项**，规则见第 6.2 节。

## 4. 数据边界

```text
EgangnalLexicon.sqlite（只读，随 App 打包）
        │  LexiconRepository 协议：搜索 / 分级浏览 / 取词条
        ▼
LexiconCatalogStore（@MainActor @Observable，页面状态）
        │  用户点击“加入单词本”
        ▼
WordBookRepository → WordEntry（SwiftData，个人可写）
```

- 浏览与搜索**不写任何数据**。
- 公共词库不注册为 SwiftData 模型，也不与个人词条共享唯一键空间。
- 视图不打开 SQLite、不写 SQL，也不直接操作 SwiftData；两条边界都由仓储承担。

## 5. 功能设计

### 5.1 等级浏览

- 顶部提供等级筛选：**全部 / 初中 / 高中 / 四级 / 六级**，默认“全部”。
- 多等级词条允许出现在多个筛选结果中，但公共目录中只有一条记录（等级是 `entry_level` 关系表，不是逗号拼接字符串）。
- 分页每页 **50 条**并支持页内滚动，提供上一页 / 下一页与页码信息。（原定“沿用单词本每页 20 条”，在知道实际为 7,116 条后修正：20 条/页需要 356 页，翻页不现实。详见[词库界面设计](词库界面设计.md)第 8 节。）
- 排序：默认按数据源的词频排名（`frequency_rank`，缺失时排在最后），并列时按 `search_term` 升序，保证结果稳定可测。

### 5.2 搜索

- 输入完整单词、首字母（前缀）**或中文意思**即检索；输入为空时回到等级浏览。
- 查询键 `search_term` 的规范化必须与现有英语 `WordNormalizer` 保持同一协议：去首尾空白、连续空白折叠为单个空格、Unicode NFC、按 `en_US_POSIX` 转小写。
- 前缀检索使用**范围查询**（`search_term >= :q AND search_term < :q_upper`）而不是 `LIKE`，以便稳定命中 B-tree 索引。
- **中文释义检索**：输入含 CJK 字符时，改为在 `chinese_translation` 上做参数化子串匹配，多词之间取与关系。中文与英文两种模式**二选一**而非取并集——释义含 `vt.`、`[计]` 等 ASCII 内容，并集会让输入 `v` 命中全部动词。实测全表扫描 1–2 ms，不需要索引；若将来切到 `full` 模式（76 万条）需改用 FTS5。详见[词库界面设计](词库界面设计.md)第 5.2 节。
- 搜索结果同样分页，并显示命中数量。
- 边界：空查询、仅空白、超长输入、无结果、含特殊字符（`%`、`_`、引号）都必须有明确行为，且由于使用参数绑定，特殊字符只作为普通字符处理。

### 5.3 词义遮盖

- 词性词义区域支持整体遮盖，用于“看单词回忆词义”。
- 遮盖是**视图状态**，不写入数据库，也不改变词条本身。
- 与单词本遮盖的差异需明确：单词本按阅读状态重置，词库默认**不持久化**遮盖状态，切换筛选或搜索后恢复为显示。该差异必须写入辅助功能标签与界面提示，避免用户误以为状态丢失。
- 提供“全部显示 / 全部遮盖”的显式控制，并遵循 `accessibilityReduceMotion`。

### 5.4 收录到单词本

> **2026-09-11 修订**：原规则为“不产生 `WordOccurrence`”。实际使用后改为**收藏计入当日出现记录**，并用批次来源区分词库收藏与文档导入。详见 [ADR-003](../architecture/架构决策-003-公共词库与个人单词本分离.md) 决策 4。

- 每个词条提供“加入单词本”操作；已收藏的词条按钮变为“取消收藏”，再次点击即撤销。
- **收录字段**：仅 `term` + **浏览级短释义**（写入 `WordEntry.meaning`）。**不收录**音标、英文释义、等级标签、频率排名。
  写入短释义是为了让单词本里一个词保持一行左右；完整释义随时可在词库查到。
- **幂等**：同一语言空间内，规范化词形相同即视为已存在；同一天重复收藏只提示，不新增记录。
- **首次释义优先不变**：若该词已由 Markdown 导入存在，收藏**不覆盖**其既有释义。
- **计入当日**：收藏会创建（或复用）当天的“词库收藏批次”，并写入一条当日出现记录，
  因此该词会出现在日期模式的今天分组里。
- **一个词只收藏一次**（已确认的产品规则，2026-09-11）：按钮只有“已收藏 / 未收藏”两态，
  已收藏时再次点击是取消而不是再记一次，因此界面不会在同一词上累积出多个收藏日期。
  数据模型允许一个词有多条不同日期的收藏记录，但那只用于异常路径下的自洽，
  **不能据此认为“跨日重复收藏会成为高频词”——界面做不到这件事**。
- **取消收藏**：只删除来源为词库收藏的出现记录。
  - 词条唯一来源是词库收藏 → 整体删除；
  - 词条另有文档导入或手动来源 → **只移除收藏记录**，词条与其文档日期原样保留，并向用户说明；
  - 从未收藏过、或来自文档导入／手动新增 → 不删除任何内容，提示到单词本中管理。
- 收录成功/失败必须有明确反馈，失败时不得留下部分写入。

## 6. 与单词刷的联动

### 6.1 收录词条进入抽题范围

> **2026-09-13 更正**：本节原判断为「收录词条没有出现记录，因此当前进不了单词刷，必须显式修改」。
> 该判断写在 5.3.2 修订收藏规则**之前**，现已过时。5.3.2 起收藏会写入**当日**出现记录，
> 而 `WordQuizCandidateSource.isImported` 的判定正是「有出现记录」，因此**收藏词条早已进入默认抽题池**，
> 5.5 **不需要**为此改动候选层代码，只需用测试锁定。详细核实见[词库与单词刷联动实现设计](词库与单词刷联动实现设计.md)第 2 节。

```text
候选规则：拥有出现记录（Markdown 导入或词库收藏）→ 进默认抽题池
高频词规则：保持不变，只统计文档日期
取消收藏：删掉收藏写入的出现记录 → 该词自动退出抽题池
```

这是本设计中唯一与单词刷候选层相关的一条，且**只依赖既有实现**，`WordQuizCandidateSource` 无需改动。

### 6.2 测验用简短释义

单词刷以 `meaning` 作为四选一选项文本。词库释义是多行长文本（中位 27 字符、p90 55、最长 196），直接使用必然破坏选项布局。派生规则（Swift 侧纯函数实现，便于迭代与单测）：

1. **选行**：按还原后的换行拆行，取第一个“形如 `词性 + 释义`”的行。跳过以 `[` 开头的领域标注行（如 `[计]`、`[古]`）和不含词性前缀的语法说明行（如 `run的过去式和过去分词`）。勘察显示 **99.62%** 的词条第一行即为合格行，仅 27 条需要回退。
2. **回退**：若没有任何合格行，取第一个非空行并保留原文（不剥离词性前缀），避免产生空释义。
3. **去词性前缀**：剥离行首的词性缩写与分隔点。必须覆盖 ECDICT 的实际用法，尤其是用 **`a.`** 表示形容词（不是 `adj.`），以及 `ad.`、`vt.`、`vi.`、`int.` 等。
4. **取首义项**：按 `；`、`;`、`,` 切分，取第一段。
5. **收敛**：折叠空白、去除首尾标点、限制最大长度（暂定 12 个字符），超出时截断并加省略号。

派生规则必须有版本号与固定样例测试，样例直接取自勘察得到的最长词条（`round`、`set`、`snap`、`run`、`slip`）与 27 条无前缀特例（`a`、`AM`、`are`、`antisocial`、`attent`）。选择在 Swift 侧而非构建期派生，是为了在文字规则调整时无需重建数据库。

⚠️ **实际落地与本节原始描述有两处差异（2026-09-13 记录）**：

1. **收藏链路写入单词本的是 `browsingDisplay` 而不是 `shortGloss`**：它**保留**词性前缀（`vt. 放弃, 抛弃…`），
   与词库列表、单词本三处显示保持一致。第 3 条"去词性前缀"因此没有作用到收藏链路，仅 `shortGloss` 使用。
   完整对比见[词库与单词刷联动实现设计](词库与单词刷联动实现设计.md)第 2.1 节。
2. **截断冲突已在 5.5 落地**：同一题内两个选项显示文本相同时，组卷时换掉该干扰项；
   凑不齐 4 个选项则明确失败，不静默少给选项。实测冲突规模为 **93 组 / 189 条词**，
   其中 684 条词条的显示文本触到 12 字上限。

### 6.3 按等级直接发起单词刷（本阶段可选，已后置到 5.5.1）

在词库的等级结果或搜索结果上提供“开始单词刷”，把当前筛选范围直接作为抽题范围。改动边界：

- `WordQuizScope` 新增等级范围分支（现有 `allImported` / `date` 不变）；
- `WordQuizCandidateSource` 增加“词库候选”来源；
- `WordQuizStore` 增加“范围来自词库”的入口。

⚠️ 需注意的接口约束：`WordQuizCandidate.id` 是 `UUID`，而词库来自 SQLite。ADR-003 决策 5 要求构建期生成确定性 UUID，从而**无需修改该类型**。

**后置原因（2026-09-13）**：「范围 = 当前筛选」在搜索场景下不是等级枚举能表达的，而 `WordQuizScope` 是
`Hashable, Sendable`、装不下 `[LexiconEntry]`；干扰项池需要整个词库（7,116 条）而 `WordQuizStore.load()`
目前只读个人单词本；从词库页发起还需要一条跨工作区请求通道。三项都是结构性改动，
见[词库与单词刷联动实现设计](词库与单词刷联动实现设计.md)第 3.4 节。

## 7. 界面与交互

- 入口：英语空间 → “学习资料” → 词库（替换现有“功能监修中”占位）。
- 结构：顶部筛选与搜索区 + 中部列表区 + 底部分页区；返回总览入口保持左上角现有范式。
- 列表行：`单词`（主信息）、`音标`（次要信息，缺失时不占位）、`词性词义`（可遮盖）、右侧收录按钮。
- 视觉不新增体系：颜色、间距、圆角取 `AppTheme` 与 `AppPalette`；长词条按现有单词本自动换行规则处理。
- 无障碍：筛选、搜索框、遮盖开关、收录按钮、分页按钮均需稳定标识与语义标签；遮盖状态下辅助功能仍应能读到真实释义（避免双重遮挡），具体策略在实现评审时确认。
- 最小窗口 `820 × 560` 下，筛选、搜索、列表、分页不得遮挡或横向溢出。

> 第 7 节只给出界面的范围性约定。**完整的排版规格、悬停浮层、字号常量、无障碍标识与界面验收标准见 [词库界面设计](词库界面设计.md)**；两处冲突时以界面设计文档为准。

## 8. 容量与包体积

以下是 **5.1 数据勘察的实测结果**（不再是估算），详见 [ECDICT 数据勘察报告](ECDICT数据勘察报告.md)：

| 项目 | 实测值 |
| --- | --- |
| 词条数（初中/高中/四级/六级并集去重） | **7,116** |
| 各等级数量 | 初中 1,603 / 高中 3,677 / 四级 3,849 / 六级 5,407 |
| 音标缺失 | 67 条（0.94%） |
| 规范化后重复 / 查询键碰撞 | 0 / 0 |
| SQLite 产物（含索引）**实测** | **2,617,344 字节 ≈ 2.5 MB** |
| 当前安装包对比 | 线上包约 4.2 MB；仓库内两个 Sparkle zip 合计 7.8 MB |

结论：**比原估算（4–8 MB）更小**，放在本地对磁盘毫无压力，**不需要服务端**。词库产物提交到 Git，体积可接受；原始 ECDICT CSV **不提交**（63 MB，属可重新取得的构建输入）。

**规模扩展选项**（需产品决定，见第 11 节）：ECDICT 基础版中共有 8 个分级标签，全部并集为 **14,942 条**，预计产物约 2.2 MB。若认为 7,116 条不足，可把考研、托福、雅思、GRE 也纳入等级，无需改动 schema。若未来产物超过约 50 MB，再评估 Git LFS 或服务端增量更新。

### 9.1 需要的一次 SwiftData 变更（已完成）

`WordEntry.isManuallyCreated: Bool` → `WordEntry.source: WordEntrySource`（`String` 存储的稳定枚举：`markdownImport` / `lexiconCollection` / `manual`）。

- 属于**加字段 + 数据回填**的轻量迁移；迁移前必须有测试证明旧库可正常打开且来源判定正确。
- 迁移完成后，`WordQuizCandidateSource` 与单词本的“未归档单词”分组需一起改用新枚举，不能保留两套判定。

实际落地方案（2026-09-11）：

- 旧字段用 `@Attribute(originalName: "isManuallyCreated")` 重命名为 `legacyIsManuallyCreated` **保留**，同时新增 `sourceRawValue`；
  直接删除旧字段会丢失“手动 / 导入”的历史区分，无法回填。
- `WordEntry.source` 是唯一判定入口：`sourceRawValue` 有效时用它，为空（旧库尚未回填）时**退回旧布尔字段推断**。
  这一步是必需的——若默认成 `markdownImport`，历史手动词条会在日期模式里凭空消失。
- `AppDependencies` 在创建仓储后执行一次 `migrateLegacyEntrySourcesIfNeeded()`；失败只记录日志、不阻塞启动，
  因为 `source` 的退回逻辑仍然给出正确语义，下次启动会重试。
- “未归档单词”分组本就按 `occurrenceDates.isEmpty` 判断，未使用 `isManuallyCreated`，因此无需改判定，只更新了文案。
- 旧字段在失去用途后可以移除，属于后续清理项。

## 10. 错误与空状态

| 场景 | 期望行为 |
| --- | --- |
| 词库资源缺失 | 页面显示明确错误，不崩溃；浏览与收录禁用，个人单词本不受影响 |
| `schema_version` 不兼容 | 显示明确错误，不尝试查询未知结构 |
| SQLite 打开或查询失败 | 显示可理解错误，记录日志，不静默返回空列表 |
| 搜无结果 | 显示空状态与当前关键词，不显示“载入中” |
| 等级筛选无数值 | 显示对应空状态 |
| 收录失败 | 明确错误提示，词条状态保持“未收录”，不留部分写入 |

已确认的产品规则（2026-09-11 确认，前六项全部采用原暂定方案）：

1. 初中与高中**分开**展示。
2. 多等级词**可以**在多个筛选中重复出现，公共目录仍只有一条记录。
3. 无中文释义的词**排除**。
4. 收录前**允许**用户编辑词义，但已有个人释义不被覆盖。
5. 遮盖状态**不**跨页面持久化。
6. 等级速测（6.3）**本阶段可后置**到 5.5。
7. **已确认**：首版词库规模维持四等级并集 **7,116 条**（实测产物 2.5 MB）。全部 8 个标签的 14,942 条扩展方案暂不采用；将来如需扩展，只需调整等级映射并重建，schema 无需改动。

## 12. 测试与验收

### 12.1 单元测试

- 等级映射：单标签、多标签、无标签词条的筛选结果，且各等级数量与勘察基线偏差不超过 1%。
- 搜索：完整词、前缀、大小写与全角/半角、仅空白、特殊字符、无结果。
- 分页：0、1、20、21、40、41 条边界（与单词本同一套边界）。
- 排序稳定性：`frequency_rank` / `bnc_rank` 为 `0` 时按缺失排在最后，并列时结果顺序可复现。
- 换行还原：包含字面 `\n` 的词条（如 `round`）展示时不含 `\n` 字样；不含转义的词条保持原样。
- 释义派生：多行、词性前缀（含 `a.`）、`[计]` 等领域标注、语法说明行、27 条无前缀特例、超长截断。
- 释义派生冲突：同一题内两个选项截断后显示文本相同时必须被检测并规避。
- 收录：新增、重复幂等、已存在不覆盖释义、不产生出现记录、来源标记正确。
- 高频词不受影响：收藏后同一词的文档日期数不变。
- 只读与参数绑定：特殊输入不改变查询语义。
- schema 不兼容与资源缺失的明确失败。

### 12.2 界面验收

- 英语空间可进入词库；日语空间仍显示占位。
- 四级筛选切换后列表内容与数量正确，分页边界正确。
- 搜索完整单词与首字母均能命中，清空后回到等级浏览。
- 遮盖可切换且不改变词条数据；切换筛选后恢复显示。
- 收录后单词本出现该词，来源为词库收藏，且不进入日期分组。
- 已收录词条显示“已在单词本”，重复点击不新增记录。
- `820 × 560` 与深浅两套主题下，筛选、搜索、列表、分页均可用且不遮挡。
