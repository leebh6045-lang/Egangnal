# 每日学习反馈实现设计

- 状态：已完成
- 日期：2026-08-19
- 关联决策：[ADR-001：本地优先与长期累计计时](../architecture/架构决策-001-本地优先学习计时.md)
- 关联设计：[长期学习计时实现设计](长期学习计时实现设计.md)

## 1. 目标与边界

首页挂历通过日期底色反馈当天的整体学习投入，不显示当天学习时长数字，也不新增学习记录列表、打卡统计或可编辑历史。

当天整体投入定义为英语和日语两个学习空间的实际计时秒数之和：

- 合计达到 15 分钟（`>= 900` 秒）：橙色状态。
- 当天进入过学习空间但合计不足 15 分钟：灰色状态。
- 当天没有进入过学习空间：无反馈底色。

长期累计时长仍然按语言空间独立保存，不能通过首页反馈修改。

## 2. 本地数据模型

继续使用 SwiftData（底层 SQLite），新增 `DailyStudyActivity` 模型。每个本地日期和语言空间最多一条记录：

```text
DailyStudyActivity
  identityKey: String       // yyyy-MM-dd|japanese 或 yyyy-MM-dd|english，唯一
  dateKey: String            // 用户本地日历中的日期，不保存时分秒
  languageSpaceID: String    // japanese 或 english
  studiedSeconds: Double     // 当天该语言的实际累计秒数
  hasEntered: Bool           // 当天是否进入过该语言空间
  updatedAt: Date
```

按语言拆分保存而不是只保存首页合计，原因是长期时长的语言隔离规则仍然成立，也为未来按语言展示反馈保留数据基础。首页查询时只合并同一天的两条记录，不显示合计数值。

记录数量上限约为每天两个条目，一年约 730 条，对本地空间可以忽略。

## 3. 计时写入事务

计时控制器继续使用 `SuspendingClock` 计算真实经过的秒数，使用本地 `Calendar` 确定日期归属。长期累计和每日聚合必须在同一个仓储保存事务中提交：

1. 进入语言空间时，立即为当天该语言创建或更新记录，并设置 `hasEntered = true`；即使随后只停留几秒，也能显示灰色反馈。
2. 检查点、语言切换、返回总览、应用失焦、系统休眠和应用退出时，计算本次增量。
3. 将增量同时加入语言长期总时长和每日语言记录的 `studiedSeconds`。
4. 两项数据一次性保存成功后，才推进计时起点；失败时保留完整的待提交增量和日期分配，不能只保存其中一项。

每日反馈不创建学习会话记录。若同一天多次进入同一语言空间，只累加秒数并保持一条记录。

## 4. 跨日期与本地时间

持续学习跨过午夜时，增量按照本地日期边界拆分。例如 23:55 到 00:10 的 15 分钟，前一天得到 5 分钟，后一天得到 10 分钟。

单调时钟负责计算总秒数，墙上时间只负责把已计算秒数分配到日期，避免用户修改系统时间影响长期累计。日期键使用事件发生时的本地日历，已有记录不会因为时区改变而被重命名。

## 5. 日历状态与连接形状

查询某个月时，对每个日期合并英语和日语记录：

```text
没有记录                         -> none
存在进入记录，合计秒数 < 900     -> visited
合计秒数 >= 900                  -> completed
```

`visited` 使用浅灰色底色，`completed` 使用橙色底色。颜色放入 `AppPalette`，分别为浅色和深色主题提供高对比度值。

一个日期底色只有在以下条件同时满足时才与相邻日期连接：

- 相邻日期存在；
- 两个日期状态相同，橙色不能连接灰色；
- 两个日期位于同一周行，周一和周日边界强制断开。

渲染时只让同色连续段的首尾保留圆角，中间日期使用方形连接边。日期数字和底色仍占用固定网格单元，不改变挂历高度。

当前日期原有的蓝色强调改为细描边或小标记，避免覆盖当天的橙色或灰色反馈；反馈底色仍是日期的主视觉状态。

## 6. 持久化与迁移

新增模型后继续使用现有 `ModelContainer`。首版采用 SwiftData 的轻量模型扩展，不改变现有 `StudyTimeRecord`、单词本和用户资料字段；读取旧数据时自动视为没有每日反馈记录，不补造历史日期。

每日记录查询通过仓储完成，视图不直接访问 `ModelContext`。仓储必须校验日期键、语言 ID、秒数有限且非负、唯一键不重复。持久化失败沿用现有计时错误提示，不能把未成功保存的日期显示成已完成。

## 7. 测试与验收

领域和仓储测试覆盖：

- 初次进入但 0 秒离开生成灰色状态。
- 合计恰好 15 分钟和超过 15 分钟均为橙色；不足 15 分钟为灰色。
- 日语和英语同日累加后按合计秒数判断，长期累计仍分别保存。
- 多次进入同一语言同一天不会产生重复记录。
- 跨午夜增量准确拆分到两个日期。
- 重启或重新打开仓储后每日反馈保持一致。
- 长期时长保存和每日聚合保存失败时不会出现部分提交。

日历 UI 测试覆盖：

- 无记录日期没有底色。
- 灰色连续段可以连接，橙色连续段可以连接，灰色和橙色之间断开。
- 周末与下一周的日期不会连接。
- 今天的标记不会覆盖反馈底色。
- 展开和收起挂历不影响首页语言入口位置。
- 首页不出现当天学习时长数字。

## 修订（2026-09-14）：日历下方的唯一今日摘要

阶段 7 第三轮允许首页显示当天英语与日语的合计投入，但只在日历下方出现一次：

- 分钟数取当日有效 `studiedSeconds` 之和并向下取整，不写回存储。
- 同一区域显示 `尚未开始`、`未达标` 或 `已达标`；达标阈值仍为 900 秒。
- 卡片下方不得重复时长或达标状态，改为只读最近单词页摘要。
- 这不是长期累计、会话历史或打卡功能，原有计时写入与日期底色规则不变。

因此，本节旧验收项“首页不出现当天学习时长数字”由“首页仅在日历下方出现一次今日摘要”取代。

## 修订（2026-09-15）：恢复同周同色连接

2026-09-14 第三轮曾把第 5 节的连接条带改为每天一个独立圆点（见《前端视觉优化实现设计》11.4）。
用户复核后要求恢复：同一周行内同色相邻日期相连，橙色与灰色之间、周日与下周一之间断开，没有可连接邻居时为独立圆。
第 5 节的规则自本日起重新生效，11.4 中的相反结论作废。

- 连接判断在 `Domain/CalendarActivityLayout.swift`，单元测试 `calendarActivityOnlyConnectsSameWeekAndSameStatus`
  覆盖同色相连、跨色断开、跨周断开、首尾格与无记录日期不连接、越界索引不崩溃。
- 条带高度、独立圆直径与今天描边直径共用同一个值（默认窗口 23 pt，最小窗口 19 pt），条带首尾与圆严丝合缝。
- 达标阈值、状态映射与日历下方的今日摘要不变。
