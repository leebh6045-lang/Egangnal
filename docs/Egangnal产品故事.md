# Egangnal 产品故事

## 1. 它为什么出现

Egangnal 起源于一个很个人的需求：为开发者自己建立一片安静、可掌控的语言学习空间。

许多主流语言学习产品以任务、计划、连续打卡和完成率推动用户前进。这些机制对一些人有效，但它们也可能把学习变成另一份必须完成的清单。当生活中的其他事情占据时间，某一天没有完成任务时，产品给出的提醒、断签或进度落后，反而会制造挫败感。

Egangnal 选择了另一种方向：

- 不规定今天必须学什么；
- 不要求连续登录；
- 不用完成率评价使用者；
- 不把暂时离开解释为失败；
- 只在使用者主动进入时，提供一个低干扰的学习环境。

它并不试图取代市场上的综合语言课程，也不负责替用户安排完整的学习路线。它更像一张属于个人的书桌：自己收集的单词在这里，真实投入也被安静地保留下来。什么时候坐下、停留多久、学习哪门语言，都由使用者自己决定。

## 2. 产品要解决的问题

这个产品主要解决三个问题。

### 2.1 降低开始学习的阻力

语言学习并不是生活的唯一部分。如果每次开始前都要面对课程计划、任务列表、复杂分类和进度压力，启动本身就会消耗意愿。

因此，Egangnal 的首页只保留英语和日语两个入口。点击后直接进入该语言上次使用的功能，不再经过多余的中间选择页。工作区中的功能通过靠近顶部才出现的悬浮栏切换，常态下把主要空间留给正在进行的事情。

### 2.2 让长期投入可见

创作者在玩游戏时很关注 Steam 的游戏时长和成就系统。游戏时长不会规定今天必须玩多久，它只是长期、诚实地记录“我确实在这件事上投入过”。回看时长时，人能重新感受到过去投入的重量，也能回味过程中的心得和收获。

Egangnal 把这种反馈映射到语言学习：

- 英语像一款独立的游戏，拥有自己的累计时长；
- 日语像另一款独立的游戏，也拥有自己的累计时长；
- 进入哪门语言的空间，就为哪门语言计时；
- 切换语言时，旧空间停止，新空间开始；
- 离开学习空间、应用失活或电脑休眠时停止；
- 累计时长只能由实际使用产生，不能手工增加或修改。

这里记录的不是一次次学习会话，也不是今天完成了几项任务，而是长期总投入。它给出正反馈，但不制造义务。

### 2.3 把个人收集的生词变成可使用的内容

创作者日常学习语言的材料主要来自视频和 Markdown 文档。项目没有一开始就追求庞大的内容平台，而是先选择更小、更明确的切入点：单词。

用户从应用导出固定格式的空白 Markdown 模板，在熟悉的编辑器里填写单词和中文意思，再把文档导入对应语言空间。导入后，文本被解析为一条条本地结构化词条，可以分页阅读、按模板顶部的文档日期回顾、遮盖单词或词义辅助记忆，也可以进入单词刷检验掌握情况。

模板是输入工具，不是数据库备份。导出只生成带当天日期和空白分隔行的模板，不会把已有单词导出。

## 3. 产品定位

Egangnal 当前面向开发者本人，是一个本地优先、单用户、单窗口的 macOS 桌面应用。

它的目标不是：

- 成为覆盖听说读写的完整课程平台；
- 与成熟商业语言软件争夺通用市场；
- 用算法替用户决定学习计划；
- 用连续打卡、排名或惩罚维持活跃；
- 在当前阶段建设账号、社区或云同步系统。

它的目标是：

- 提供一个愿意随时打开的个人学习空间；
- 缩短从“想学习”到“开始学习”的路径；
- 让英语和日语的词库数据及长期投入保持清晰边界；
- 用长期时长、日历颜色和练习反馈给出温和的正反馈；
- 让数据首先属于本机上的使用者。

## 4. 从构思到当前形态

### 4.1 两个独立的语言空间

英语和日语不是首页上的两个筛选标签，而是两个真正独立的学习空间。每个空间拥有自己的：

- 单词及其文档日期；
- 单词刷候选范围；
- 长期累计学习时长；
- 上次使用的功能位置。

同一个词即使分别出现在两个语言空间，也不会跨语言合并。进入英语空间后，顶部功能栏也不会切换到日语；如需换语言，先回到首页，再进入另一门语言。这是有意选择的保守设计，用更少的顶部控件保持语言归属清晰。

### 4.2 长期计时，而不是手动打卡

计时从进入语言空间开始，覆盖该空间内的单词本、单词刷和未来功能。用户不能点击“增加一小时”，也不需要每次学习后手工登记。

累计值以精确秒数保存，界面转换为小时并显示一位小数。颜色随长期投入变化：早期保持主题默认文字色，之后依次进入蓝色、紫色和橙色阶段。它表达成长，但不将阈值变成必须完成的任务。

### 4.3 日历上的“圈地”反馈

首页不展示“今日总学习时长”数字。当天反馈只通过挂历日期底色表达：

- 当天进入过任一语言空间，但英语与日语合计不足 15 分钟：灰色；
- 当天两种语言合计达到 15 分钟：金黄色；
- 同一周、同一颜色的相邻日期可以横向连接；
- 不同颜色不连接，跨行日期也不连接。

这个设计保留“我今天来过”和“我今天有一段真实投入”两层反馈，同时避免首页变成统计仪表盘。它不是连续打卡：中断一天不会出现惩罚，也不会抹去过去的投入。

### 4.4 单词本：把输入变成自己的资料

单词本服务于用户主动收集的内容，而不是向用户推送统一词库。

当前规则包括：

- 模板顶部记录文档日期；
- 使用全角双竖线分隔单词和中文意思；
- 一次导入要么完整成功，要么完整失败；
- 同一语言中的同一个词只保留一个主词条；
- 出现不同中文意思时，保留最早成功导入的释义；
- 同一词在至少两个不同日期出现时，用蓝色标记为高频词；
- 默认模式每页 20 条，日期模式按模板顶部的文档日期回看；
- 点击单词或词义可以用圆角矩形遮盖，再次点击恢复；
- 编辑是一项显式操作，不在默认阅读状态下误触发生。

这些规则让单词本更像个人积累，而不是另一个需要完成的课程列表。

### 4.5 单词刷：检验，而不是制造成绩压力

单词刷从用户已经导入的词库中抽题，不额外提供陌生的公共题库。

- 默认范围从全部可用词中随机抽取最多 20 个；
- 也可以选择某个模板文档日期对应的单词；
- 简单模式只有词义选择题；
- 深度模式先完成词义选择，再完成拼写；
- 正确和错误都有明确的视觉反馈；
- 可选择两种点击音效，也可以关闭；
- 有错题时可以只重试错题；
- 测试结束后不保存成绩历史。

最后一点符合产品边界：单词刷帮助当下复习，不建立排名、连续记录或新的进度负担。

### 4.6 安静但有个性的界面

产品的视觉方向是简洁、沉浸、低干扰，但不等于没有性格。

- 应用使用自己的浅色和深色主题，不跟随系统自动变化；
- 主题从右下角按钮位置以圆形波纹覆盖整个窗口，标题栏和页面同步变化；
- 语言卡片可以显示淡化的英语、日语封面；
- 页面可以显示模拟写字板的细长网格；
- 设置中可以关闭两种个性化效果；
- 功能顶部栏只在鼠标靠近其区域时出现，不挤压页面布局；
- 进入工作区时顶部栏会短暂显示，帮助第一次使用的人发现导航。

这些效果的作用不是展示动画技巧，而是让打开应用这件事本身更顺畅、更愿意重复。

## 5. 名称的由来

`Egangnal` 来源于 `Language` 的倒写构思。

```text
Egangnal
   ↓ 字母逆序重排，中间 n 独立变化为 u
Language
   ↓ 两侧文字出现
For Language Study
```

按照创作者的命名构思，`Language` 倒写后，为了兼顾读音和独特性，将原来的 `u` 上下翻转为 `n`，最终形成 `Egangnal`。

这个命名后来不只停留在文字解释里，也成为首页的一项交互：

1. 初始状态显示 `Egangnal`；
2. 点击品牌后，八个字母以各自稳定身份动态重新排列；
3. 中间的 `n` 独立旋转并变化为 `u`；
4. 排列完成后，`For` 和 `Study` 从两侧淡入；
5. 再次点击 `Language`，两侧单词先淡出，字母再重排回 `Egangnal`。

因此，名称本身表达了产品的主题，也把“重新组织语言”变成了可以感知的视觉动作。

## 6. 产品原则

### 6.1 主动，而非被动

内容来自用户自己的学习过程。应用提供容器、工具和反馈，不把统一课程强加给使用者。

### 6.2 记录投入，而非评判表现

时长和日历只说明发生过什么，不判断使用者是否足够努力。没有断签，没有落后，也没有失败天数。

### 6.3 简短路径，而非层层菜单

首页进入语言后直接回到上次功能；工作区顶部栏按需出现；常用阅读和练习尽量留在一个稳定页面内。

### 6.4 本地优先，而非先建设平台

单词、时长和偏好保存在本机。当前不需要用户登录，也不需要维护业务后端。Sparkle 和 GitHub 只承担应用版本发布，不承载用户学习数据。

### 6.5 小步演进，而非一次做大

每个大阶段先明确需求、数据含义、异常边界和验收标准，再进行代码改动。当前没有明确价值的能力不提前开发，以免复杂度超过个人应用真正需要的范围。

### 6.6 稳定体验，而非只追求视觉效果

主题动画不能让控件跳动，悬浮栏不能挤压功能页，窗口缩放不能破坏核心布局，存储失败不能静默丢数据。视觉和动效必须服从可用性与健壮性。

## 7. 为什么选择本地优先

Egangnal 当前只服务一个人在一台 Mac 上的学习，因此本地持久化比自建服务器更符合实际需求：

- 没有账号和密码管理；
- 不需要支付数据库或业务服务器成本；
- 离线也能使用单词本和计时；
- 私人学习数据不会为了一个尚不存在的同步需求离开设备；
- 开发可以集中在真实使用体验上。

本地优先并不意味着永远拒绝同步。它只是要求未来在真正出现跨设备需求时，再单独讨论身份、冲突合并、隐私、迁移和费用，而不是现在为想象中的规模付出复杂度。

应用更新是另一件事。Sparkle 从公开托管地址读取 appcast 并下载新版安装包；Egangnal 的更新代码不会向更新服务上传单词、学习时长或其他学习数据。

## 8. 当前边界

截至当前版本，首页、主题、长期计时、日历反馈、单词本、单词刷、个性化设置和检查更新已经接入应用。

以下内容需要明确区分：

- “学习资料”在顶部栏中已经有入口，但页面仍显示“功能监修中”；Markdown/纯文本资料复制和只读阅读尚未实现。
- 个人资料相关模型、仓储、Store 和旧组件仍在代码中，但当前首页没有显示个人信息卡片，用户无法编辑昵称。
- 单词刷不保存历史成绩或中途答题进度。
- 没有云同步、账号、社区、排行榜或业务后端。

这些边界不是缺陷清单，而是当前阶段有意保持的范围。下一项能力只有在能继续降低启动阻力、增强真实学习反馈或改善个人资料使用方式时，才值得进入设计阶段。

## 9. 可以继续生长的方向

按照现有产品原则，后续更适合优先考虑：

- 完成只读的 Markdown/纯文本学习资料空间；
- 为本地数据提供清晰、可验证的备份与恢复方式；
- 继续改善单词阅读和复习体验，而不是堆叠统计指标；
- 在真实需要出现后，再评估跨设备同步；
- 持续检查窗口缩放、键盘操作、VoiceOver 和减少动态效果体验。

无论增加什么功能，都应先回答三个问题：它是否降低了开始学习的阻力？它是否尊重使用者自己的节奏？它提供的是正反馈，还是悄悄制造了另一项任务？

这三问构成 Egangnal 后续演进最重要的产品判断标准。
