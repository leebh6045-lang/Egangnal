# Egangnal 产品需求

## 1. 产品定位

Egangnal 是开发者本人使用的本地 macOS 语言学习空间。产品不提供强制任务、连续打卡、完成率或惩罚性反馈，学习节奏完全由使用者决定。

产品通过以下方式提供正反馈：

- 展示长期、真实的累计学习投入。
- 为不同语言提供互相独立的资料空间。
- 让进入学习资料的路径尽可能短。
- 保持界面安静、稳定、低干扰。

## 2. 核心概念

### 2.1 语言空间

语言空间是资料和学习时长的归属边界。首版内置：

- 日语空间
- 英语空间

两个空间的数据完全独立：

- 日语资料只属于日语空间。
- 英语资料只属于英语空间。
- 日语和英语分别拥有独立的单词本，词条与出现日期不能跨空间合并。
- 每个空间维护自己的累计学习时长。

首版不开放动态添加语言。模型使用稳定的语言空间 ID 关联资料与时长，避免把日语和英语拆成散落的专用字段即可，不提前设计动态语言管理能力。

### 2.2 长期累计学习时长

累计时长的语义参考 Steam 对不同游戏游玩时长的统计：进入某个语言空间即开始累计该语言的学习时间，在该空间内浏览资料或使用其他功能时持续累计。

计时规则：

1. 日语和英语分别保存独立累计值。
2. 同一时刻全局最多只有一个语言空间计时。
3. 从日语空间切换到英语空间时，日语立即暂停，英语立即开始；反向切换同理。
4. 离开语言空间回到总览页时，当前语言暂停。
5. 应用进入非活跃状态或系统休眠时，当前语言暂停，但保留当前正在展示的语言空间。
6. 应用重新变为活跃状态时，如果主窗口仍展示某个语言空间，则自动恢复该语言的计时；如果展示总览页，则保持暂停。
7. 主窗口关闭或应用退出时暂停。重新打开应用不会补算关闭期间的时间；再次进入语言空间后继续累计。
8. 不保存每次进入语言空间产生的会话记录，只保存累计时长。
9. 不允许通过界面或公开业务接口手工修改累计时长。
10. 内部以秒保存精确值；界面转换为小时并显示一位小数，例如 `120.1 小时`。
11. 显示层采用标准四舍五入，显示结果不会写回或覆盖内部精确值。

首版只提供一个主窗口，不支持同时打开多个学习窗口。计时状态属于整个应用，由主窗口当前展示的页面决定；未来若增加多窗口，需要另行编写窗口所有权决策文档。

## 3. 工作台与导航

### 3.1 总览工作台

总览工作台承担以下职责：

- 展示低对比度的可交互品牌文字，默认显示 `Egangnal`，点击后可展开为 `For Language Study`，再次点击恢复。
- 展示英语、日语两个封面卡片入口；入口只显示语言名称，不显示累计时长或续接功能文案。
- 卡片下方只读展示最近三个日期页及词数；存在未归档词时额外展示未归档词数。该区域不提供导航或编辑。
- 页面右侧常驻展示当前月日历和达标日期；顶部日期与日历、语言卡片共用同一内容宽度。
- 日历下方唯一展示今日英语与日语合计学习分钟数及 15 分钟目标状态。
- 总览不展示跨语言长期累计时长，日语和英语的长期时长始终保持独立语义。
- 日期和挂历不提供计划、事件、打卡、编辑或学习会话历史功能。
- 首页右下角提供主题切换按钮，按浅色、暖纸、石墨（深色）循环，主题选择本地保存；设置页可直接选定。
- 应用使用自己的三套主题，不跟随 macOS 系统外观自动变化。

### 3.2 语言空间

进入语言空间后：

- 自动激活该语言的长期计时。
- 以小时为单位显示该语言的累计学习时长，精确到一位小数。
- 可以浏览该语言的资料列表。
- 可以导入本地 Markdown 或纯文本资料。
- 可以打开资料并只读查看。
- 可以进入当前语言的单词本，导入结构化单词文档并浏览词条。
- 后续可以承载语法整理等功能。

## 4. 本地资料

### 4.1 首版支持范围

- 支持导入 `.md` Markdown 文件。
- 支持导入 `.txt` 纯文本文件。
- 导入时将文件复制到应用管理的本地目录。
- 导入后的文件只能阅读，不提供编辑能力。
- Markdown 以渲染后的只读内容展示，不直接显示源码。
- 首版渲染标题、段落、强调、列表、引用、代码和网页链接。
- 网页链接只在用户明确点击后交给系统浏览器打开。
- 首版不加载远程图片，不渲染相对图片，不允许打开 `file://` 本地链接，也不执行内嵌 HTML。
- 资料必须归属于一个语言空间。
- 支持从资料空间删除资料及应用管理的副本。

### 4.2 暂不支持

- 云端同步。
- 在线资料抓取。
- 富文本编辑。
- PDF、Word、视频等复杂格式。
- Markdown 附件管理和复杂图片资源迁移。
- 对原始导入文件保持双向同步。

## 5. 个人信息

首版个人信息包含：

- 默认头像占位符。
- 可编辑昵称。
- 昵称通过本地持久化保存。

自定义头像作为后续小阶段实现。首版仅使用固定占位符，不为尚未确定的头像流程提前增加存储字段或编辑入口。

## 6. 单词本

### 6.1 模板导出与导入

- 单词本导出只生成空白 Markdown 模板，不导出现有词条，也不承担备份功能。
- 模板使用 UTF-8、`.md` 扩展名和本地当天日期，固定日期格式为 `yyyy年MM月dd日`。
- 日期行后必须有两行空行；随后是括号括起的简短填写说明，说明下方再保留两行空行。
- 导出模版预置 20 行空白词条，每行分隔符为两个全角竖线 `｜｜`（两个 `U+FF5C`）；左侧不放置占位空格，右侧保留六个 ASCII 空格。
- 用户填写后的词条格式为 `language｜｜      语言`，单词和中文意思都不能为空。
- 导入时兼容旧版分隔符左右各六个或各三个 ASCII 空格的文档。
- 导入错误行号按双竖线行顺序从 1 开始；未填写的双竖线占位行不算错误，也不要求填满 20 行。
- 导入时读取文档顶部日期，并将词条解析为 SwiftData 结构化数据；不把该文件复制到只读资料目录。
- 一次导入必须整体成功或整体失败。空文件、错误日期、错误分隔符、已填写行的空字段和非 UTF-8 内容需要返回明确错误；模版中未填写的双竖线占位行应被忽略。
- 发起文件选择时固定目标语言空间，导入过程中即使页面切换也不能改变归属。

### 6.2 重复词与释义

- 英文词忽略首尾空白、连续空白、大小写和 Unicode 组合形式后判定重复；日文词忽略首尾空白、连续空白和 Unicode 组合形式后判定重复。
- 同一语言空间内的重复词共享一个主词条，日语和英语之间绝不合并。
- 主词条使用最早成功写入数据库的中文意思；后续导入的不同意思不覆盖它。
- 同一词在同一文档日期只保存一条出现记录，重复导入同一天的数据保持幂等。
- 同一词在至少两个不同文档日期出现时为高频词；同一天出现多次只贡献一个日期。
- 文档日期是单词内容元数据，不是学习时长、打卡或学习会话记录。

### 6.3 浏览与编辑

- 默认模式按主词条分页，每页固定 20 条，同一个词只显示一次，高频词使用蓝色文字标记。
- 默认分页模式只读，不能增删改词条。
- 日期模式按文档日期倒序分组，每页显示一天的全部导入词条，页面内部可以上下滚动。
- 用户可以显式进入编辑模式后新增、修改或删除词条；不能在只读分页状态中直接修改。
- 手动新增词条没有文档日期，不自动归入当天；日期模式将其放入独立的“未归档单词”分组。
- 删除主词条时同时删除其全部出现记录。修改主词条只修改当前展示内容，不改写历史文档日期。

## 7. 非功能需求

- 核心状态变更必须有单元测试。
- 计时切换必须避免重复累计和负时长。
- 存储失败必须有可理解的错误反馈，不能静默丢失数据。
- 资料导入必须使用稳定的应用内相对路径，不能依赖原始文件继续存在。
- 界面需要适配窗口缩放、深色模式、键盘操作和 VoiceOver 基础语义。
- 标题栏背景需要与页面连续融合，不显示独立分界线。
- 首版以 `820 × 560` 作为最小窗口验收尺寸。
- 代码保持小模块、明确所有权和单向数据流。
- 关键设计原因、状态约束和异常处理使用简洁中文注释说明。
- 单词导入解析与数据库写入必须分层，视图不能自行解析 Markdown 或直接访问 SwiftData。
- 单词导入、去重和编辑不能产生跨语言数据污染。

## 8. 明确非目标

当前阶段不实现：

- 学习任务、计划或提醒。
- 连续打卡和完成率。
- 单次学习会话历史。
- 手工修正累计学习时长。
- 学习笔记或 Markdown 编辑。
- 账号系统、云数据库或跨设备同步。
- 自动识别用户是否真正阅读了资料。
- 将单词本模板导出作为词条备份或数据迁移方案。
- 跨语言合并重复词或共享中文意思。
